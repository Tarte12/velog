> 강의는 HTTP 웹 개발 지식인데, 왜 인터넷 네트워크부터 설명하는 걸까?

## 인터넷 통신
- 컴퓨터와 컴퓨터가 통신할 때, 복잡한 인터넷 망을 어떻게 통해서 지나가는가?

>이걸 하기 위해 IP가 필요함

## IP(인터넷 프로토콜)

### IP : 인터넷 프로토콜 역할
- 지정한 IP 주소(IP Address)에 데이터 전달
- 패킷(Packet)이라는 통신 단위로 데이터 전달

>패킷(Packet)?
- 패키지와 버킷의 합성어

### 전달 과정
- 출발지 IP, 목적지 IP 등 정보를 담아 전달하면, 클라이언트 패킷을 노드들이 정해진 협약에 따라 목적지까지 전달함
- 서버 패킷도 같은 방식으로 클라이언트에게 전달

### IP 프로토콜의 한계

**비연결성**
- 패킷을 받을 대상이 없거나 서비스 불능 상태로 패킷 전송
=> 클라이언트 : 대상 서버가 패킷을 받을 수 있는 상태인지 모름
**비신뢰성**
- 중간에 패킷이 사라지면?
=> 중간 서버가 문제가 생기면(노드가 꺼져 버리거나) 패킷 소실 가능성
- 패킷이 순서대로 안 오면?
=> 패킷의 용량이 클 때, 이 내용을 끊어서 보냄 => 최종적으로 순서대로 내용이 도착하지 않을 가능성
**프로그램 구분**
- 같은 IP를 사용하는 서버에서 통신 애플리케이션이 둘 이상이면?
- EX) 내 PC에서 음악도 듣고, 게임도 함 <= 같은 IP 주소일 경우

> 그렇다면 위의 문제를 해결을 어떻게 해야 할까?
그래서 나온 게 **TCP, UDP**

## TCP, UDP

### 인터넷 프로토콜 스택의 4계층

|인터넷 프로토콜 스택의 4계층|
|---|
|애플리케이션 계층 : HTTP, FTP|
|전송 계층 : TCP, UDP|
|인터넷 계층 : IP|
|네트워크 인터페이스 계층|

### TCP 특징
- TCP(Transmission Control Protocol) : 전송 제어 프로토콜

**3가지 대표적 특징**
- 연결 지향 : TCP 3 way handshake (가상 연결)
=> 비연결성 해결
- 데이터 전달 보증
=> 메시지 누락을 알 수 있음
- 순서 보장

- 신뢰할 수 있는 프로토콜
- 현재는 대부분 TCP 사용

### UDP 특징
- UDP(User Datagram Protocol) : 사용자 데이터그램 프로토콜

- 하얀 도화지에 비유(기능 거의 X)
- 연결 지향 - TCP 3 way handshake X
- 데이터 전달 보증 X
- 순서 보장 X
- 데이터 전달 및 순서가 보장되지 않지만 단순하고 빠름
**정리**
- IP와 거의 같음 => +PORT, +체크섬 정도만 추가
- 애플리케이션 추가 작업 필요
=> TCP는 그냥 있는 거 쓰는 거고, 내가 더 최적화하고 싶으면 UDP 써서 추가 작업(원하는 걸 애플리케이션 레벨에서 만들면 됨)

>IP랑 다름이 없으면 왜 UDP를 쓰는 거지?
**PORT** 기능은 존재함! => PROT가 뭘까?
+ 단순하고 빠름!

## DNS

**IP 그대로의 문제**
- IP 주소 그대로 기억하기 어려움
- IP 변경될 수 있음

- 전화번호부(같은 서버를 줌)
- 도메인 명을 IP 주소로 변환
