## 1.2 컴퓨터의 데이터가 전기 신호로 변환되는 과정
![](https://velog.velcdn.com/images/emprimula/post/631cb426-9467-4328-a945-b4377e59f05f/image.png)

1. **응용 계층**
	- 3-way 핸드셰이크가 완료되어 연결이 확립된 상태라고 가정
    - 컴퓨터에서 웹 브라우저를 이용해 웹 서버의 웹 사이트에 접속하기 위한 요청을 보냄
    - 웹 서버에 있는 html 데이터를 얻어야 함 => `GET /index.html HTTP/1.1 ~1` 같은 HTTP 메시지를 보냄
2. ** 전송 계층**
	- TCP 헤더가 붙음, TCP 헤더가 붙은 데이터 => **세그먼트**
    - 출발지 포트 번호, 목적지 포트 번호 
    - 출발지 포트 번호(웹 브라우저)은 잘 알려진 포트가 아닌 포트(1025~) 중에서 무작위로 선택됨
    - 목적지 포트 번호는 HTTP이므로 80번 포트
3. **네트워크 계층**
	- IP 헤더가 붙음, IP 헤더가 붙은 데이터 => **패킷**
    - 출발지 IP 주소, 목적지 IP 주소 
4. **데이터 링크 계층**
	- 이더넷 헤더가 붙음, 이더넷 헤더가 붙은 데이터 => **이더넷 프레임**
    - 출발지 MAC 주소, 목적지 MAC 주소
5. **물리 계층**
	- 전기 신호로 변환하여 네트워크 전송
    - 전기 신호로 변환하는 장비 => **랜 카드**
    
# 2. 스위치와 라우터에서의 데이터 전달과 처리
> 스위치와 라우터에서 데이터가 처리되는 과정에 대해

## 2.1 스위치에서의 데이터 전달과 처리
- 동일한 네트워크(LAN) 내에서 데이터를 주고받을 때 사용
=> 그러니까 데이터 링크 계층이 랜에서 데이터를 송수신할 때 필요한 계층인데, 이 역할을 스위치가 담당해 준다는 거임
- 스위치는 **MAC 주소**를 기반으로 작동하며, 특정 목적지 장치의 MAC 주소를 학습하여 해당 포트로만 데이터 전송

- **물리 계층 -> 데이터 링크 계층 -> 물리 계층**
	- 컴퓨터의 데이터가 전기 신호로 변환되어 전달
    - 데이터를 전기 신호로 변환하여 전송
    
## 2.2 라우터에서의 데이터 전달과 처리
=> 네트워크 계층에서 서로 다른 네트워크 사이의 통신을 담당하고 있는데 이 역할을 라우터가 하는 것

- **물리 계층 -> 데이터 링크 계층 -> 네트워크 계층 -> 데이터 링크 계층 -> 물리 계층**
	- 전기 신호가 전달됨
    - 데이터 링크 계층에서 목적지 MAC 주소와 자신의 MAC 주소를 비교 => 주소가 같을 경우 이더넷과 헤더와 트레일러를 분리하는 역캡슐화 수행
    - 네트워크 계층에서 라우팅 테이블과 목적지 IP 주소 비교
    - 라우팅을 함 => 현재 출발지 주소(`192.168.1.10`)을 라우터의 외부 IP 주소(`172.16.0.1`)로 변경
    - 그런 다음 데이터 링크 계층에서 라우터 B로 보내기 위해 이더넷 헤더와 트레일러를 붙임
    - 물리 계층에서 데이터를 전기 신호로 변환하고 네트워크로 전달

# 3. 웹 서버에서의 데이터 전달과 처리

## 3.1 웹 서버에서의 데이터 전달과 처리

> IP주소 = 집 주소, MAC 주소 = 아파트 동/호수 or 방 번호

### 왜 데이터 링크 계층에서 MAC 주소를 식별하고 네트워크 계층에서 IP 주소를 식별하는 걸까? (아직 안 찾아봄)
- 네트워크 계층/라우터: 택배 회사 => 전국 단위의 큰 그림을 봄 각 지역 우체국(라우터)에 도착하면 거기부터는 지역 내 작은 배송 시스템에 맡김
- 데이터 링크 계층/스위치: 아파트 경비원 => 아파트 단지라는 한정된 공간에서만 작동

- **물리 계층**
	- 스위치 B로부터 전기 신호로 변환된 데이터 전달
- **데이터 링크 계층**
	- 목적지 MAC 주소와 자신의 MAC 주소 비교
    - 주소가 같으면 이더넷 헤더와 트레일러를 분리하고 네트워크 계층에 전달
- **네트워크 계층**
	- 목적지 IP 주소와 자신의 IP 주소를 비교
    - 주소가 같으면 IP 헤더를 분리하고 전송 계층에 전달
- **전송 계층**
	- 목적지 포트 번호를 확인해서 어떤 애플리케이션으로 전달해야 하는지 판단
    - TCP 헤더를 분리해서 응용 계층에 전달
- **응용 계층**
	- 웹 서버의 응용 계층에 `GET /index.html HTTP/1.1 ~1` HTTP 메시지가 전달됨
