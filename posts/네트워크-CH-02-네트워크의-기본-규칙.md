## 1. 네트워크의 규칙
### 1.1 프로토콜
- 일상생활에서 지켜야 하는 규칙이 있는 것처럼, 네트워크에서도 통신하기 위한 **규칙(약속)**을 지켜야 함
- **프로토콜(protocol)**: 통신을 하기 위한 규칙
- 데이터를 어떻게 교환할 건지에 대한 규칙을 정의한 것으로, 네트워크의 각 장치가 동일한 규칙을 따라야 데이터 전송이 가능함

#### 주요 네트워크 프로토콜
- HTTP/HTTPS: 웹에서 데이터를 주고받는 프로토콜
	- HTTPS가 보안이 강화된 버전
- FTP: 파일 전송 프로토콜
	- 서버와 클라이언트 간의 파일을 주고받을 때 사용
- SMTP: 이메일 전송에 사용되는 프로토콜
- TCP/IP: 네트워크 계층에서 데이터를 전달하고, 신뢰성 있는 데이터 전송을 보장하는 프로토콜

## 2. OSI 모델과 TCP/IP 모델
### 2.1 OSI 모델
- **OSI 모델**: ISO(국제표준화기구)에서 만든 공통적으로 사용하기 위한 표준 규격
	- 네트워크 기술의 기본이 되는 모델
    - 데이터의 송수신 => 컴퓨터에서 컴퓨터로 데이터를 전송하는 형태
    - 컴퓨터 내부에서 이것을 위해 여러 일을 하는데, 이 일을 7개의 계층으로 함
    - 이 **7개의 계층**이 **OSI 모델**
    - 계층 대신 **레이어**라고도 함
![](https://velog.velcdn.com/images/emprimula/post/a98dd251-842b-48f3-b5d1-a0446202abe2/image.png)
	- 통신할 때 데이터는 맨 위의 응용 계층(7계층)에서 순차적으로 아래 계층으로 전달
    - **응, 표, 세, 전, 네, 데, 물**
    <BR>
    
   | 계층 (위→아래) | 이름                   | 주요 역할                           | 대표 프로토콜 / 기술         | 백엔드 관점 포인트                         |
| --------- | -------------------- | ------------------------------- | -------------------- | ---------------------------------- |
| **7계층**   | **응용 계층**<BR>애플리케이션 (Application) | **애플리케이션에 대한 서비스를 제공** <BR>사용자와 가장 가까운 계층. 응용프로그램이 네트워크 사용 | HTTP, FTP, SMTP, DNS | 우리가 구현하는 API, 브라우저 통신 (HTTP 요청/응답) |
| **6계층**   | **표현 계층**(Presentation)    | **데이터 변환**<BR>데이터 형식 변환, 암호화/복호화, 인코딩         | JPEG, MPEG, SSL/TLS  | HTTPS 암호화(TLS) / JSON 인코딩 등        |
| **5계층**   | **세션 계층** (Session)         | **연결 설정, 유지, 종료. 세션 관리 **           | NetBIOS, RPC, SSL    | 로그인 상태 유지, 세션 관리 흐름 이해             |
| **4계층**   | **전송 계층** (Transport)       | **신뢰할 수 있는 통신 구현** <BR>데이터의 전달 보장. 포트 번호 사용            | TCP, UDP             | HTTP는 TCP 기반 / 포트(80, 443 등) 중요    |
| **3계층**   | **네트워크 계층** (Network)       |**다른 네트워크와 통신하기 위한 경로 설정 및 논리 주소 결정**<BR> 목적지 주소(IP)로 경로 설정, 라우팅          | IP, ICMP, ARP, 라우터   | IP 주소 관리, 서브넷팅, ICMP(ping) 등       |
| **2계층**   | **데이터 링크 계층** (Data Link)   | **네트워크 기기 간의 데이터 전송 및 물리 주소 결정** <BR> MAC 주소 기반 통신. 프레임 생성            | Ethernet, MAC, 스위치   | 이더넷, MAC 주소 기반 통신 흐름               |
| **1계층**   | **물리 계층** (Physical)        | **시스템 간의 물리적인 연결과 전기 신호를 변환 및 제어** <BR>전기/광 신호로 0과 1 전달                | 케이블, 허브, 전압 신호       | 실제 하드웨어. 개발자는 거의 신경 안 씀            |
  
- 송신 측의 7계층과 수신 측의 7계층을 통해 데이터를 주고받음
- 송신 측: 데이터를 보내기 위해 **상위 계층 -> 하위 계층**으로 데이터 전달
  	- 각 계층은 **독립적**이므로 데이터가 전달되는 동안 다른 계층의 영향을 받지 않음
- 수신 측: **하위 계층 -> 상위 계층**으로 전달된 데이터를 받음

## 3. 캡슐화와 역캡슐화

### 3.1 캡슐화/역캡슐화
  
    ![](https://velog.velcdn.com/images/emprimula/post/f5e9a840-cf90-4ae7-8679-4a368f8aa155/image.PNG)

  - **헤더**: 데이터를 보낼 때 데이터의 앞부분에 전송할 떄 필요한 정보를 붙여 다음 계층으로 보내는데, 이 정보를 의미
  	- **데이터를 전달받을 상대에 대한 정보** 포함
  	- **[필요한 정보(헤더) | 송신 데이터]** -> 이 구조로 다음 계층에 보냄
  <br>
- **캡슐화**: 이 헤더를 붙여나가는 것
  	- 상위 계층의 헤더와 하위 계층의 데이터 부분에 포함시키고 해당 계층의 헤더를 삽입하는 과정
  ![](https://velog.velcdn.com/images/emprimula/post/05827f64-d5e2-4d99-8ad0-34e9a13d7860/image.png)
	- 응용 계층의 데이터가 전송 계층으로 전달 => **세그먼트** or **데이터그램화**가 되며 TCP 헤더가 붙여짐
	- 인터넷 계층으로 가면서 IP 헤더가 붙여지며 => **패킷화**
 	- 링크 계층으로 전달되면서 프레임 헤더와 프레임 트레일러가 붙여지며 => **프레임화**
  <BR>
- **역캡슐화**: 데이터를 받은 쪽에서 헤더를 제거하는 것
  	- 하위 계층에서 상위 계층으로 가며 각 계층의 헤더 부분을 제거하는 과정
![](https://velog.velcdn.com/images/emprimula/post/e8e3ecca-54ef-42d9-9a9a-b5d5229dc599/image.png)
	- 캡슐화 데이터를 받게 되면 링크 계층부터 올라가면서
    - **프레임화** -> **패킷화**
    - **패킷화** -> **세그먼트/데이터그램화**
    - **세그먼트/데이터그램화** -> **데이터**
    
 ### 3.2 PDU
 - **PDU**: 네트워크의 어떠한 계층에서 계층으로 데이터가 전달될 때 한 덩어리의 단위
 - 헤더 + 헤더로드 구성, 계층마다 부르는 명칭이 다름
    - 헤더: 제어 관련 정보
    - 페이로드: 데이터
    - 명칭
    	- 응용 계층: 메시지
    	- 전송 계층: 세그먼트(TCP), 데이터그램(UDP)
    	- 인터넷 계층: 패킷
    	- 링크 계층: 프레임, 비트
 - PDU 중 아래 계층인 비트로 송수신하는 것이 모든 PDU 중 가장 빠르고 효율성이 높음
  - 응용 계층에서는 문자열을 기반으로 송수신 => 헤더에 다른 값을 넣는 확장이 쉽기 때문
    
 ## 4. VPN
- **Virtual Private Network(가상 사설망)**
- 가상 통신 터널을 만들어 기업 본사 or 지사 같은 거점 간을 연결하여 통신하거나, 외부에서 사내에 접속하는 것을 의미
- **인터넷 VPN**
    - 인터넷 VPN은 거점 간 접속과 원격 접속 연결이 있음
    - 둘 다 일반 인터넷망 사용
    - 거점 간 접속: IPsec이라는 암호 기술 프로토콜을 사용하여 접속
    - 원격 접속: 외부에서 사용하는 컴퓨터나 ㅏ사내 컴퓨터를 연결하기 때문에 암호화된 통신로를 만든다
- **IP-VPN**
    - MPLS라는 기술을 사용해 인터넷망이 아닌 **통신 사업자 전용 폐쇄망**을 사용
    - MPLS는 폐쇄망을 사용하기 때문에 제삼자에 의한 해킹이나 데이터 변조의 위험 X
    - 따라서 암호화 기능 필요 X
