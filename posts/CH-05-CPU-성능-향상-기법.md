# 05-1 빠른 CPU를 위한 설계 기법
> - 클럭, 코어, 스레드
> - 멀티코어, 멀티스레드

## 클럭

### 클럭
**컴퓨터 부품들은 "클럭 신호" 주기에 맞춰 명령어들이 실행되며 동작**
- 클럭 속도가 높을수록 => CPU의 명령어 사이클은 더 빠르게 반복
- 따라서 클럭 속도가 높은 CPU가 성능이 일반적으로 좋음 => CPU의 속도 단위로 간주

### 클럭 속도
- 헤르츠(Hz) 단위로 측정되며, 1초에 클럭이 몇번 반복되는지 나타냄
- 1Hz는 1초에 클럭 1번이 반복된 것을 의미
- 클럭 속도는 일정하지 않음 -> 고성능을 요구할 땐 클럭 속도를 높히고, 유연하게 낮추기도 함
- 이에 따라 기본 클럭 속도(Base)와 최대 클럭 속도(Max) 등으로 표기
- 오버클럭킹(overclocking): 최대 클럭 속도를 강제로 끌어올려서 CPU 성능을 향상시키는 기법

### 클럭 속도의 한계
- 속도만 높인다고 무조건 CPU가 빨라지는 것이 아님
- 고성능을 요구하는 작업을 장시간 처리 시 발열 문제 심각해질 수 있음

## 코어와 멀티코어

**CPU 성능을 높히는 방법**
- CPU의 코어 수와 스레드 수를 늘려서 성능을 향상시킴
- 기술의 발전에 따라 CPU 내부의 명령어를 처리하는 부품인 코어를 여러 개 설계 가능

**코어(core)**
- 명령어를 실행하는 부품

**멀티코어(multi-core)
- 멀티코어(multi-core) CPU: 코어를 여러 개 포함하고 있는 CPU로 멀티코어 프로세서라고도 불림
- 멀티코어 처리 속도는 단일 코어보다 일반적으로 빠름

### 멀티코어 종류

|코어 수|프로세서 명칭|
|---|---|
|1|싱글코어|
|2|듀얼코어|
|3|트리플코어|
|4|쿼드코어|
|6|핵사코어|
|8|옥타코어|
|10|데카코어|
|12|도데카코어|

### 멀티 코어의 한계
- CPU 연산 속도가 코어 수에 비례해 증가하는 것은 X
- 코어에 처리할 연산이 전절히 분배되지 않으면 코어 수에 비해 성능 향상 크지 않음
- 처리할 작업량보다 코어 수가 지나치게 많아도 성능 향상 크지 않음
- **코어마다 처리할 명령어들을 얼마나 적절히 분배하는지에 따라 연산 속도가 크게 달라짐**

## 스레드와 멀티스레드

**스레드(thread)**
- 실행 흐름의 단위, 하드웨어적 스레드 / 소프트웨어적 스레드
- 하드웨어적 스레드 : CPU에서 사용되는 스레드
- 소프트웨어적 스레드: 프로그램에서 사용되는 스레드

**하드웨어적 스레드**
- 하나의 코어가 동시에 처리되는 명령어 단위
- 논리 프로세서(logical process)라고도 부름
- 여러 스레드를 지원하는 CPU는 하나의 코어로 여러 개의 명령어를 동시에 실행 가능
- 멀티스레드(multithread) 프로세서: 하나의 코어로 여러 명령어를 동시에 처리하는 CPU로 멀티스레드 CPU로도 불림 => 하이퍼스레딩(hyper-threading): 인텔의 멀티스레드 기능

**소프트웨어적 스레드**
- 하나의 프로그램에서 독립적으로 실행되는 단위
- 일반적으로 **스레드**라고 칭함
- 하나의 프로그램에서 서로 독립된 작업들은 동시에 실행될 수 있음
- 1코어 1스레드 CPU도 소프트웨어적 스레드를 여러 개 실행 가능
- **소프트웨어적 스레드는 프로그램의 여러 부분을 동시에 실행하는 것**

**멀티스레드 프로세서**
- 멀티스레드 프로세서를 구성할 때 레지스터가 중요한 역할
- 하나의 명령어를 처리하려면 하나의 레지스터 세트가 필요
- 따라서 멀티스레드 프로세스는 여러 명령어를 동시에 처리하기 위해 레지스터 세트를 여러 개 들고 있음

# 05-2 명령어 병렬 처리 기법

## 명령어 병렬 처리 기법(Instruction-Level Parallelism, ILP)
- 명령어를 동시에 처리해 CPU를 쉬지 않고 작동시키는 방법
- 명령어 파이프라이닝, 슈퍼스칼라, 비순차적 명령어 처리 등

>그러니까 많은 소프트웨어적 스레드를 동시다발적으로 처리하기 위해 고려되는 기법이 명령어 병렬 처리 기법인 건가?

## 명령어 파이프라인
- 명령어는 같은 처리 단계는 동시에 실행 불가
- CPU는 **다른 단계에 있는 여러 명령어 동시에 실행 가능**

**명령어 처리 단계**
(1) 명령어 인출(Instruction Fetch)
(2) 명령어 해석(Instruction Decode)
(3) 명령어 실행(Execute Instruction)
(4) 결과 저장(Write Back)

### 명령어 파이프라인(Instruction Pipeline)
- 동시에 여러 개의 명령어를 겹쳐서 실행하는 기법
- 명령어를 겹쳐서 실행하면 하나씩 실행하는 것보다 훨씬 효율적 처리 가능

### 파이프라인 위험(Pipeline Hazard)
- 특정 상황에서 파이프라이닝이 성능 향상에 도움을 주지 못하는 경우 의미
- 데이터 위험, 제어 위험, 구조적 위험 등

#### 데이터 위험(data hazard)
- 데이터 의존적인 두 명령어를 실행하려고 할 때, 파이프라인이 제대로 동작하지 않는 경우
- 명령어 사이 **데이터 의존성**에 의해 발생

#### 제어 위험(control hazard)
- 분기 등으로 인한 "프로그램 카운터의 갑작스러운 변화"로 발생
- 분기로 인해 명령어 파이프라인이 미리 처리 중이던 명령어가 쓸모없게 되어버리는 현상
- 분기 예측(branch prediction): 제어 위험 방지를 위해 사용, 프로그램이 어디로 분기할지 예측하고 그 주소를 인출하는 기술

#### 구조적 위험(structurl hazard)
- 명령어 파이프라인에서 서로 다른 명령어가 동시에 ALU, 레지스터 등의 CPU 부품에 접근할 때 발생
- 자원 위험(resource hazard)라고도 불림
## 슈퍼스칼라(superscalar)
- CPU 내부에 여러 개의 명령어 파이프라인을 포함한 구조
- 요즘 대부분 CPU는 여러 개 파이프라인을 사용
**슈퍼스칼라 프로세서**
- 슈퍼스칼라 구조의 명령어 처리가 가능한 CPU, 슈퍼스칼라 CPU라고도 부름
- 장점: 이론적으로 파이프라인 개수에 비례해 프로그램 처리 속도 빨라짐
- 단점: 실제로 파이프라인 위험 등 예상치 못한 상황에서는 파이프라인 개수에 비례해 빨라지지 X
- **파이프라인 위험을 방지하는 방향으로 고도화된 설계 필요**
![](https://velog.velcdn.com/images/emprimula/post/21cb352b-8006-40a7-a030-48038e2b2c9e/image.png)

## 비순차적 명령어 처리(Out-of-order execution, OoOE)
- 명령어를 순차적으로 실행하지 않는 기법
- 선순위 명령어가 실행되는 명령어들과 데이터 의존성이 있을 때, 순서를 바꿔 처리해도 되는 후순위 명령어들을 먼저 처리하는 방법
- CPU 성능 향상에 크게 기여한 기법으로, 오늘날 대부분의 CPU가 차용한 기법
- 비순차적 명령어 처리가 가능한 CPU는 명령어가 어떤 명령어들과 데이터 의존성이 있는지, 순서를 바꿔 실행할 수 있는지 판단할 수 있어야 함

# CISC와 RISC

**명령어의 형태**
- 효율적인 파이프라이닝을 위해 명령어가 최적화되어야 함
- 최적화된 명령어란 파이프라이닝을 하기 쉬운 형태로 된 명령어를 의미

## 명령어 집합(Instruction set)
- CPU가 이해할 수 있는 명령어들의 모음
- 일종의 CPU 언어로 이해할 수 있음
- CPU마다 ISA가 다를 수 있음
- 명령어 집합 구조(Instruction Set Architecture, ISA)라고도 부름
=> CPU 명령어 이해 방식에 따라 컴퓨터 구조 및 설계 방식이 달라질 수 있어 **구조**라는 단어 사용

**ISA 특징**
- CPU가 어떤 ISA를 쓰느냐에 따라 많은 것이 달라질 수 있음
=> 제어장치가 명령어를 해석하는 방식
=> 사용하는 레지스터의 종류와 수
=> 메모리 관리 방법
- **ISA는 CPU 하드웨어 설계 방식에 큰 영향을 미침**
- **명령어 병렬 처리에 적합한 ISA와 적절하지 못한 ISA가 존재함**

> ISA마다 무엇이 다른지, 명령어 병렬 처리에 적합하고 적합하지 않은 ISA가 무엇이고 무슨 차이가 있는지?
## CISC

### CISC(Complex Instruction Set Computer)
- 복잡한 과정 처리가 가능한 다양한 명령어를 활용하는 CPU 설계 방식
- 명령어 형태와 크기가 다양한 가변 길이 명령어 활용
**장점**
- 상대적으로 적은 수의 명령어로도 프로그램 실행 가능
- 메모리를 최대한 절약하며 쓸 수 있어 과거에 인기가 높았음
**단점**
- 명령어의 크기가 다르고, 명령어 실행 시간 일정하지 않음
- 복잡한 명령어로 명령어 하나를 실행할 때 여러 클럭 주기 요구

#### CISC의 한계
- CISC는 명령어마다 처리 시간이 달라지기 때문에 명령어 파이프라인 구현이 어려움
** => 명령어가 규격화되어있지 않아 파이프라인을 어렵게 만듦 **
- CISC는 복잡한 연산을 가능케하는 다양한 명령어들이 존재하지만 대부분 사용 빈도가 낮음
** => 자주 사용되는 명령어만 쓰임 **

## RISC

### RISC(Reduced Instruction Set Computer)
- CISC의 한계를 극복하기 위해 등장한 명령어
**특징**
- CISC에 비해 명령어 종류가 적음
- 명령어를 규격화해 되도록 1클럭 내외로 실행되는 명령어 지향
- 고정 길이 명령어 활용
**장점**
- 명령어 파이프라인에 최적화
**단점**
- 프로그램을 실행할 때 CISC보다 많은 명령어 필요

#### RISC의 메모리 접근
- RISC는 메모리에 직접 접근하는 명령어를 load, store 두 개로만 표현
- 단순화된 명령어만을 최소로 남겨 파이프라이닝을 효율적으로 가능하게
- 메모리 접근을 단순화하고, 레지스터 적극 활용
- 레지스터 이용 연산이 많고, 일반적으로 범용 레지스터의 수도 많음
