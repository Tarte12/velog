> **응용 계층, 웹 서버 구조, DNS 이름 해석 구조, 메일의 송수신 구조**

# 1. 응용 계층의 역할
## 1.1 응용 계층의 역할

- **응용 계층**: 애플리케이션과 데이터를 주고받기 위해 필요
	- 응용 계층 = **세션 계층 + 표현 계층**
    - 사용자 측(클라이언트)의 요청을 전달하기 위해 => 통신 대상(서버 등)이 이해할 수 있는 메시지(데이터)로 변환하고 전송 계층으로 전달하는 역할
    - **서비스를 요청하는 측(클라이언트)**: 웹 브라우저, 메일 프로그램 등
    - **서비스를 제공하는 측(서버)**: 웹 서버 프로그램, 메일 서버 프로그램 등
    - 애플리케이션이 응용 계층에서 동작
    
 => 클라이언트 측 애플리케이션(웹 브라우저, 메일 프로그램 등)이 서버 측 애플리케이션(웹 서버 프로그램, 메일 서버 프로그램 등)과 통신하려면 **프로토콜**을 사용
 
|프로토콜|내용|
|---|---|
|HTTP| 웹 사이트 접속|
|DNS| 이름 해석|
|FTP| 파일 전송|
|SMTP| 메일 송신|
|POP3|메일 수신|

- **이름 해석**(name resolution): 네트워크에서 컴퓨터나 네트워크 장비에 붙여진 이름을 기반으로 IP주소를 알아내는 행위
	=> 이것을 위해 **DNS**(Domain Name System) 사용

# 2. 웹 서버의 구조(웹 사이트 접속)
## 2.1 WWW
- World Wide Web
- **HTML, URL, HTTP** 세 가지 기술 사용
- HTML(Hyper Markup Language): 웹 페이지에서 문장 구조나 문자를 꾸미는 **태그**를 사용하여 작성하는 **마크업 언어**
    - 제목, 목록 같은 문장 구조 지정 or 이미지 파일을 보여 줄 때 태그 사용
    - **하이퍼텍스트**(Hypertext)를 작성하는 마크업 언어
    - 하이퍼텍스트로 문자와 이미지를 표시 or **하이퍼링크**(Hyperlink) 사용 가능
    - 하이퍼링크는 보통 **링크**(link)라고 부름 => 웹 사이트에서 아이콘이나 버튼 등에 있는 링크를 클릭하면 다른 사이트로 이동할 수 있음
    - 이동한 사이트에서는 **html 파일**이나 이미지 파일이 웹 서버에서 전송됨
    	- 문서와 이미지를 각각 별도로 요청해서 글이 먼저 뜨고 이미지가 나중에 뜰 때가 있음
        
- URL: Uniform Resource Locator

## 2.2 HTTP
- 클라이언트(웹 브라우저)는 웹 사이트를 보기 위해 서버(웹 서버 프로그램)의 **80번 포트**를 사용해 HTTP 통신을 함
- 클라이언트에서 **HTTP 요청**(request)를 보내고,
- 서버에서 **HTTP 응답**(response)를 반환
- HTTP/1.1 버전은 keepalive 기능이 있어 데이터를 교환하는 동안엔 연결을 유지하고 데이터 교환이 끝나면 연결을 끊음
- HTTP/2 버전은 요청을 보낸 순서대로 응답을 반환하지 않아도 됨

# 3. DNS 서버의 구조(이름 해석)
## 3.1 도메인 이름
- 기본적으로 컴퓨터(서버)에서는 **IP 주소**가 있어 인터넷을 통해 웹 서버에 접속하여 웹 사이트를 볼 수 있음
- **DNS**: **URL을 IP 주소로 변환하는 서비스(시스템)**
- DNS의 **이름 해석**: IP 주소가 아닌 `http://www.~` 같은 주소를 사용하여 접속하도록 돕는 역할
- **도메인 이름**: 컴퓨터나 네트워크를 식별하기 위해 붙여진 이름
- **호스트 이름**(서버 이름): 도메인 이름 앞에 있는 `www`

### DNS 서버와의 통신 흐름
**첫 번째 DNS 서버가 도메인의 IP 주소를 아는 경우**
	1. 컴퓨터 -> DNS 서버:  이 도메인의 IP 주소는 무엇인가요? 질문
	2. DNS 서버 -> 컴퓨터: 요청에 해당하는 도메인 이름의 IP 주소를 알려 줌
	3. 컴퓨터: IP 주소로 접속
    
**첫 번째 DNS 서버가 도메인의 IP 주소를 모르는 경우**
	1. 컴퓨터 -> DNS 서버 1:  이 도메인의 IP 주소는 무엇인가요? 질문
    2. DNS 서버 1 -> DNS 서버 2:  이 도메인의 IP 주소는 무엇인가요? 질문
	3. DNS 서버 2 -> DNS 서버 1: 요청에 해당하는 도메인 이름의 IP 주소를 알려 줌
    4. DNS 서버 1 -> 컴퓨터: 요청에 해당하는 도메인 이름의 IP 주소를 알려 줌
	5. 컴퓨터: IP 주소로 접속
    
=> 요청받은 DNS 서버가 해당 도메인 이름의 IP 주소를 모르는 경우에는 다른 DNS 서버에 질의
=> DNS 서버는 전 세계에 흩어져 계층적으로 연결되어 있으므로 연계하면서 동작함

# 4. 메일 서버 구조(SMTP와 POP3)
## 4.1 메일의 송수신 구조
- 메일을 송수신할 때 필요한 **프로토콜**은 두 가지
- **SMTP**: 메일을 보낼 때 사용되는 프로토콜, 포트 번호는 **25**
	- 메일 서버 간의 메일 전송에도 사용
- **POP3**: 메일을 받을 때 사용되는 프로토콜, 포트 번호는 **110**

**흐름**
1. SMTP를 사용해 컴퓨터 1에서 메일 서버 1로 메일을 보냄
2. SMTP를 사용해 메일 서버 1에서 메일 서버 2로 메일을 보냄
3. POP3을 사용해 메일 서버 2에서 컴퓨터 2로 메일 데이터를 보냄사용해 메일 서버 2에서 컴퓨터 2로 메일 데이터를 보냄

## 4.2 SMTP에 의한 메일 송신과 메일 전송

**컴퓨터 1과 메일 서버 1의 동작 흐름**
1. 세션 시작을 통지
2. 송신자의 메일 주소를 통지
3. 목적지 메일 주소를 통지
4. 메일 본문 전송을 통지
5. 메일 본문을 송신
6. 세션 종료를 통지

**메일 서버와 메일 서버의 동작 흐름**
1. SMTP를 이용, 컴퓨터 1에서 메일 서버 1로 메일 송신
2. SMTP를 이용, 메일 서버 1에서 메일 서버 2로 메일 전송

## 4.3 POP3에 의한 메일 수신

- 메일 박스:
	- 메일을 보관하는 메일 서버의 기능
	- 메일 서버는 POP3를 이용, 메일 서버의 메일 박스에서 메일을 가져와 컴퓨터로 전송
    
**메일 수신 과정**
1. SMTP를 이용, 메일 서버 2에 메일이 도착
2. 세션을 시작
3. 컴퓨터 2에서 사용자 인증을 완료
4. 컴퓨터 2에서 자신의 메일이 있는지 확인한 후, 있다면 메일 서버 2는 확인 응답을 반환
5. POP3를 이용, 메일 서버 2의 메일 박스에서 컴퓨터 2로 메일을 가져온다.
세션을 종료
