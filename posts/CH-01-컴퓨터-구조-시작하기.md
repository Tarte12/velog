> 컴퓨터 구조 공부의 이유와 전반적인 틀에 대한 단원

# 01-1 컴퓨터 구조를 알아야 하는 이유
- 컴퓨터 구조는 실력 있는 개발자가 되려면 반드시 알아야 하는 기본 지식
=> why?

## 문제 해결
**문제 해결 능력의 향상**
1. 개발할 때 문제 없던 코드가 실제로 동작하지 않을 수 있음 -> 이것은 코드만의 문제가 아닐 수 있음
2. 컴퓨터 구조를 안다면, 문제 상황을 빠르게 진단하여 문제 해결 실마리를 찾을 수 있음
3. 실제로 채용 공고, 기술 면접에서 컴퓨터 구조 지식을 요구하는 경우가 있음

## 성능, 용량, 비용
**목적에 맞는 성능과 용량을 파악하고, 최소의 비용으로 설계할 수 있음**
1. 선택에 따라 비용이 달라짐 -> 목적에 맞게 CPU, 메모리, 보조기억장치 등을 선택할 수 있어야 함
=> 적정한 양 파악 능력 필요
2. 이것을 위해 개발한 프로그램이 어떤 환경에서 잘 동작하는지, 최소/최적 컴퓨터 환경은 어떻게 되는지 파악 필요

**컴퓨터 구조를 이해한다면 -> 프로그래밍뿐만 아니라 성능, 용량 비용을 고려할 수 있는 개발자가 될 수 있음**

# 01-2 컴퓨터 구조의 큰 그림
**컴퓨터 구조의 지식**
1. 컴퓨터가 이해하는 '정보'
2. 컴퓨터의 '네 가지 핵심 부품'

## 컴퓨터가 이해하는 정보
- 컴퓨터는 0과 1로 표현된 정보만 이해
- 0과 1로 표현되는 정보는 크게 두 가지 -> '데이터', '명령어'

**데이터(Data)**
- 컴퓨터와 주고받는 정보, 컴퓨터에 저장된 정보
- 컴퓨터가 이해하는 숫자, 문자, 이미지, 동영상 같은 '정적인' 정보

> 그러면 동적인 정보는 어떻게 저장되는 건지?

**명령어(Instruction)**
- 컴퓨터를 작동시키는 정보로 데이터 처리, 연산 등을 할 수 있게 함
- 컴퓨터를 실질적으로 동작하게 하는 더 중요한 정보 
=> 데이터 < 명령어

- 명령어는 컴퓨터를 작동시키는 정보
- 데이터는 명령어를 위한 재료

## 컴퓨터의 4가지 핵심 부품

**중앙처리장치(CPU, Central Proessing Unit)**
**주기억장치(메모리, Main Memory)**
- RAM과 ROM 존재 But 컴퓨터의 작동 원리를 파악하기 위해 중점적으로 알아아 할 것은 RAM
**보조기억장치(Sencondary Storage)**
**입출력장치(I/O(Input/Output) Device)**

> RAM, ROM의 차이, 왜 RAM을 더 중점적으로 알아야 하는지?

![](https://velog.velcdn.com/images/emprimula/post/f5386684-59bc-4b40-a398-8781e478d079/image.jpg)

1. 가장 큰 사각형 : 메인보드
2. 메인 보드 안에 '시스템버스'
3. CPU 안에 'ALU(산술논리연산장치), 제어장치, 레지스터' 존재, 메인보드 내 시스템 버스와 연결
4. 메모리 -> 메인보드 내 시스템 버스와 연결
5. 보조기억장치는 메인보드 내 시스템 버스와 연결
6. 모니터, 키보드, 마우스 => 입출력 장치, 메인보드 내 시스템 버스와 연결

> 각 부품들에 대해 알아보자

**메모리(Memory)**
=> 현재 실행되는 프로그램의 명령어, 데이터를 저장하는 부품
- 프로그램을 실행하기 위해 프로그램 정보가 메모리에 저장되어 있어야 함
- 메모리 내 저장된 정보(값)이 어디 있는지 나타내는 주소(Address) 개념 사용
- 주소를 통해 메모리의 원하는 위치에 접근하여 값을 저장하거나 가져옴
- 단점 : 가격이 비싸서 저장 단위 당 비용이 크고, 휘발성(전원이 꺼지면 저장된 내용이 날아감)

**CPU**
=> 컴퓨터의 두뇌, 메모리에 저장된 명령어를 읽고, 해석하고, 명령을 실행하는 부품
- CPU의 역할, 작동 원리를 이해하기 위해서는 CPU 내부 구성 요소를 알아야 함 => 산술논리연산장치(ALU), 레지스터, 제어장치
- ALU(Arithmetric Logic Unit) : 계산을 위해 존재하는 부품 -> 컴퓨터 내부에서 실행되는 대부분의 계산 수행
- 레지스터(Register) : CPU 내부의 임시 저장장치 -> 프로그램 실행에 필요한 값들을 임시로 저장함
=> CPU 내부에 여러 레지스터 존재
=> 서로 다른 이름과 역할
=> 대부분 용량 작음
- 제어장치(CU, Control Unit) : 제어 신호라는 전기 신호를 내보내고 명령어를 해석하는 장치
=> 제어 신호(Control Unit) : 컴퓨터 부품들을 관리하고 작동시키는 일종의 전기 신호
=> CPU가 메모리에 저장된 값을 읽을 때 메모리 읽기, 메모리에 값을 저장할 때는 메모리 쓰기라는 제어 신호를 보냄

> - **CPU** : 메모리에 저장된 값을 읽고, 해석하고, 실행하는 장치
- 내부에 **ALU, 레지스터 제어장치** 존재
- ALU는 **계산기**, 레지스터는 **임시 저장 장치**, 제어 장치는 **제어 신호 발생시키고, 명령어 해석 장치**

**보조기억장치**
=> 메모리보다 크기가 크고, 비휘발성(전원이 꺼져도 내용 유지) 기억 장치, 메모리를 보조하는 저장 장치라고 볼 수 있음
- 메모리가 "현재 실행되는 프로그램의 정보"를 가지고 있으면,
- 보조기억장치는 "프로그램으로부터 보관할 정보"를 저장
- 종류 : 하드 디스크,  SSD, USB 메모리, DVD, CD-ROM 등

**입출력장치**
=> 컴퓨터 외부에 연결되어 컴퓨터 내부와 정보를 주고 받는 장치
- 보조기억장치도 입출력장치의 일종이라고 볼 수 있음
- 종류 : 마이크, 스피커, 프린트, 마우스, 키보드 등
- 주변장치(Peripheral device) : 보조기억장치 + 입출력장치

**메인보드와 시스템 버스**

**메인보드(Main Board)**
=> 핵심 부품들을 포함해 여러 컴퓨터 부품들과 연결되는 판
=> 연결하기 위한 슬롯과 연결 단자 존재
- 마더보드(Mother Board)라고 불림
- 연결된 부품들은 **메인보드 내부 버스(bus)라는 통로를 통해 서로 정보 교환** 가능

**버스(Bus)**
=> 부품들 간 서로 정보를 주고받을 수 있는 '통로'
- 정보 목적에 따라 다양한 종류의 버스 존재
- 시스템 버스(System Bus) : 핵심 부품을 연결하는 가장 중요한 버스

**시스템 버스(System Bus) : 주소 버스 + 데이터 버스 + 제어 버스**
- 주소 버스(Address bus) : 주소 주고받는 통로
- 데이터 버스(Data bus) : 명령어와 데이터를 주고받는 통로
- 제어 버스(Control bus) : 제어 신호를 주고받는 통로
=> CPU의 제어 장치는 제어 버스를 통해 제어 신호를 내보냄

> 시스템 버스를 이해하기 위한 메모리 쓰기(Memory Wirte)과정
