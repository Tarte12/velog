## 1.3 AWS의 비용 : 초기 비용은 저렴 but 운영 비용 조금 비쌈

### 1.3.1 종량제 : 필요한 만큼만 지불
- 향후에 필요하지만 지금은 필요없는 자원을 확보할 필요 X
- 최소로 필요한 만큼만 준비해서 시작 -> 필요할 때 늘리는 방향성

### 1.3.4 AWS 요금의 장단점
#### 장점
- 초기 비용(이니셜 코스트)이 들지 않음
- 돌발적으로 접속 수가 늘어나는 웹 사이트(EX. 이벤트, 켐페인)의 경우 AWS의 유연성은 큰 장점
- 운영에 대한 부분을 맡기기 때문에 관리자 필요 X
- 기술적 지식이 부족해도 사용할 수 있는 서비스가 많음
- 회사가 전문적인 기술자를 육성하고 지속적으로 고용해야 하는 것까지 따지면 저렴한 편
- 서버나 네트워크 담당자가 없는 회사나 업무가 많지 않은 회사에서 유용함
#### 단점
- 운영 비용(러닝 코스트)가 들기 때문에, 경우에 따라 정액제 임대/지사 준비가 저렴할 수 있음
- 종량제라도 최저 요금이 있는 요금 체계 OR 사용하는 서비스 1개당 요금이 발생하는 체계 존재
- 변동이 없는 시스템은 이점이 없을 수 있음
- 이 경우 종량제보다 인건비의 축소가 비용 절감에 주목될 부분

## 1.4 AWS의 사용 방법 : 누구나 쉽게 서비스 이용 가능

### 1.4.1 서비스를 이용하기 쉬운 구조
- 전문가 불필요
- 관리 콘솔과 매니지드 서비스로 서버와 네트워크 관리를 할 수 있음

### 1.4.2 관리 콘솔
#### 관리 콘솔
- 웹 브라우저의 GUI로 AWS를 조작하는 화면
- 서비스별로 고유 화면 존재 -> 이 고유 화면에서 다양하게 관리 가능

### 1.4.3 매니지드 서비스
#### 매니지드 서비스
- AWS가 관리하는 서비스의 통칭
- 백업 및 업데이트가 자동으로 이루어짐
- 관리자가 수동으로 할 필요가 없기 때문에 관리 부담이 적어짐

### 1.4.4 보안적으로 안심할 수 있는 구성
- AWS의 매니지드 서비스의 경우 SW 업데이트와 같은 운영 업무를 자동화할 수 있기 때문에 항상 안전한 상태로 운영 가능
- 각종 기준을 충족하게끔 운용되므로 일정 수준 기대 가능
- 자사에 전묵가가 없다면 AWS가 압도적으로 보안이 안전함

# 2장 AWS를 이해하기 위한 클라우드&네트워크의 구조

## 2.1 클라우드와 온프레미스 : 클라우드 컴퓨팅의 구조
### 2.1.1 클라우드 
클라우드 : 언제, 어디서든 인터넷을 통해 접속 가능한 환경
### 2.1.2 클라우드 컴퓨팅 : 인프라를 통으로 빌리기
- 클라우드 컴퓨팅 : 크랄우드에 구축된 인프라를 활용하는 서비스나, 이것을 사용하는 것을 의미
-  가상화 기술을 사용해 언제 어디서든 마음대로 서버나 인프라를 구축하여 운영할 수 있게 구축되어 있음
- 서버와 인프라를 대여하는 것이 주류
### 2.1.3 온프레미스와 임대
- 온프레미스 : 자사가 서버 등을 구축하는 것
- 서버만 임대 -> 임대 서버
- 네트워크나 장소를 임대 -> 온프레미스
- 장점 : 자사에서 자유롭게 설게, 운영 가능
- 단점 : 서버 구성을 빈번하게 변경해야 할 수 있고, 숙력된 기술자 필요
<-> 반대말은 임대, 공용 : 자사가 소유/운영하지 않고 임대하거나 공공장소에 구축된 것을 사용
### 2.1.4 공용 클라우드와 사설 클라우드
공용 클라우드 : AWS처럼 임대하는 클라우드
사설 클라우드 : 자사에서 구축하는 클라우드
온프레미스 -> 클라우드 전환
- 자사 운영에서 임대로 바뀌는 변화
- 비클라우드에서 클라우드로 바꾸는 변화
## 2.2 가상화와 분산 처리 : 클라우드를 지탱하는 2대 기술
### 2.2.1 가상화
가상화 : 컴퓨터가 어떤 작업을 할 때 물리적인 메모리, 하드 디스크, OS 등 다양한 부품이 필요한데, 이것을 소프트웨어로 대체하는 행위를 의미함
### 2.2.2 가상화를 통한 복제
- 가상화는 물리적인 서버와 다르게 소프트웨어처럼 구축하기 때문에 서버 복제가 쉽고 대수를 늘리거나 줄이기 쉬움
### 2.2.3 분산 처리와 로드 밸런서
#### 분산 처리
- 클라우드를 지탱하는 중요한 기술 중 하나
- 기기 여러 대에 분산하여 처리하는 방법
- 웹 사이트가 이 기술을 많이 사용하며, 서버 여러 대에 분산하여 처리함
#### 로드 밸런서
- 서버 여러 대에 분배하는 장치
- 각 서버를 확인하여 부하를 분산
- 경우에 따라서는 부하가 너무 높아진 서버를 분리하기도 함
- AWS의 경우 로드 밸런서로 ELB 제공

## 2.3 SaaS, PaaS, IaaS : 클라우드의 서비스 제공 형태
2.3.1 SaaS, PaaS, IaaS -> 통칭하면 EaaS
SaaS : 애플리케이션, 플랫폼(OS), 인프라(하드웨어)
- 편리 but 자유도 낮음
- 바로 사용 가능 -> 작업량 적음
- 특별한 지식 필요 X
- 단말기 외에 준비할 것 X
PaaS : 플랫폼(OS), 인프라(하드웨어)
- 애플리케이션 마음대로 설치 가능 but 대응하지 않는 애플리케이션 존재
- 서버 관리 지식 필요
- 경우에 따라 애플리케이션 준비 필요
IaaS : 인프라(하드웨어)
- 사용할 때 세팅 필요
- 서버 관리에 대한 지식 필요
- 경우에 따라 애플리케이션 준비 필요
## 2.4 서버와 인스턴스 : 네트워크 상에 만들어진 가상 서버
2.4.1 서버란
서버 : 어떠한 서비스를 제공하는 것
2.4.2 서버는 같이 사용할 수 있다
2.4.5 서버용 OS란
- OS : 컴퓨터를 움직이기 위한 소프트웨어로, 하드웨어와 OS 위에서 동작하는 소프트웨어 사이에서 중간 역할을 한다
- EX. 유닉스, 리눅스
- 서버용 OS은 클라이언트용 OS에 비해 종류가 많다
2.4.6 인스턴스와 서버
- Amazon EC2에서 서버는 인스턴스로 생성됨
- 인스턴스 : 실체라는 의미이며 실제 가동되는 가상화 컴퓨터를 의미함
- 서버로 가동되고 있는 가상 서버(물리 서버 머신에 해당되는 컴퓨터)를 의미함
- 기능으로서의 서버는 인스턴스라 부르지 않음
