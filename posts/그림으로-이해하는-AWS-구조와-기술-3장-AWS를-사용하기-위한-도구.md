# 3장 AWS를 사용하기 위한 도구

## 3.1 AWS의 사용법과 계정 : AWS에서 제공하는 유용한 도구

### 3.1.1 AWS를 사용하기 위해 알아야 할 기본 개념

1. AWS는 클라우드 서비스이므로 '사용한 만큼 비용을 지불한다'가 기본 
-> 항상 '자신에게 최적화된 상태로 관리한다'가 클라우드를 잘 이용하는 요령

### 3.1.2 AWS는 서비스를 종합적으로 관리할 수 있다

1. 사용자가 AWS의 여러 서비르를 사용하는 경우가 많아, AWS가 서비스를 종합적으로 관리할 수 있는 편리한 기능을 제공함
2. 서버 엔지니어 같은 전문가가 없어도 운영할 수 있게 웹 브라우저로 조작할 수 있는 사용자 환경을 제공함
#### <서비스 관리 기능>
- 관리 콘솔 : 서비스 설정 화면으로, 웹 브라우저에서 사용 가능
- CLI : 명령어로 조작 가능한 명령줄 도구 -> 관리 콘솔에서 할 수 없는 것도 가능함
- IAM : 서비스를 사용하기 위한 사용자 계정 -> 그룹이나 정책 등을 일괄 관리 가능
- 비용 관리 : 비용을 그래프 등으로 확인 가능 -> 예산에 따라 관리
- CloudWatch : 감시 도구 -> 임계 값을 넘는 경우 조치를 취할 수 있음

### 3.1.3 AWS 계정

1. AWS 계정 : AWS를 사용하기 위한 계정
2. 개인뿐만 아니라 기업도 사용 -> 규모가 큰 단체도 사용할 때 장점이 많아 기업 사용자가 많음
3. 규모가 커지면 프로젝트나 비용을 관리하는 단위로 AWS 계정을 구분하여 많이 사용 -> 여러 프로젝트에서 같은 계정을 사용하면 비용이 모호해지고, 관리도 복잡해지기 때문에
(약간 음... 디스코드 계정 여러 개 사용하는 느낌인가?)

### 3.1.4 root 사용자
 
 1. root 사용자 : 로그인한 AWS 게정은 모든 조작이 가능한 관리자 권한을 가지고 있어 root 사용자라고 부름
 -> 모든 권한을 가지고 있다는 것은 편리함, but 실수할 경우 치명적이며 도용할 경우 곤란해짐
 => 따라서, AWS는 LAM 서비스만 사용하는 사용자를 별도로 관리하고 있음 
 => 일반적인 운영에는 LAM을 사용하는 경우가 일반적
 (LAM이 뭐지?)
 
###  3.1.5 서비스를 개인에 맞춰서 최적화
 1. AWS는 언제든지 시작해서 언제든지 멈출 수 있음 -> 필요할 때만 필요한 서비스를 사용하는 것이 원칙
 2. 서비스 한 개에 여러 옵션이 있음
 
##  3.2 관리 콘솔과 대시보드 : 심플하고 직관적인 관리 도구
 - 웹 브라우저로 관리 콘솔에 접속하여, AWS 서비스를 조작할 수 있음
 - 서비스별로 대시보드가 있고, 대시보드에서 각종 설정 진행
 
###  3.2.1 관리 콘솔

1. 관리 콘솔 : 웹 브라우저에서 AWS 서비스를 관리하는 화면(사용자 환경)
- 서비스별로 고유 화면(대시보드) 존재
- 서비스 설정, 리전 선택, AWS 계정 관리, 필요한 서비스나 리소스 그룹의 검색과 사용, AWS 문서의 참조 등의 관리 수행
- 명령어를 잘 알지 못하는 사람도 관리 콘솔에서 서비스 사용 가능

### 3.2.2 리전 선택

- 관리 콘솔은 지역을 대표하는 리전 단위로 조작
- 관리 콘솔은 처음 지역이 버지니아로 설정됨 -> AWS 계정으로 로그인하여 화면 오른쪽 상단 메뉴에서 사용하고 싶은 리전으로 전환 가능
- 리전은 한 번 선택되면 저장되기 때문에, 같은 리전을 사용하려면 한 번만 선택하면 됨
- 리전에 따라 사용할 수 있는 서비스와 사용할 수 없는 서비스 존재

### 3.2.3 대시보드

1. 대시보드 : 서비스르르 조작할 수 있는 메인화면
- EX) EC2 : EC2 : EC2 대시보드, S3 : S3 대시보드
- AWS의 각 서비스를 조작할 때, 리전이나 서비스를 선택하여 해당 대시보드를 사용
- 대시보드에서 사용 가능한 조작 : 서비스의 시작과 종료, 각종 설정, 현재 상태에 대한 표시 등은 공통적으로 많이 사용하는 기능

2. AWS CLI : 로컬의 명령어 단말기 OR 서버에서 명령어나 스크립트로 AWS 서비스를 빠르게 수행하기 위한 CLI이
- 스크립트를 작성해서 여러 가지 조작을 한번에 실행 OR 좀 더 자동화/프로그래밍화된 방법으로 조작할 경우에 편리함
- 파이썬의 패키지 관리 도구인 pip를 사용하여 설치

## 3.3 AWS IAM과 접근 권한 : 접근 권한 설정
- AWS I AM : AWS의 인증 방식
- AWS는 서비스를 여러 개 사용하기 때문에 적절한 관리를 위한 인증 방식이 필요
- LAM에는 사용자 외에 그룹이나 역할이 있고 일괄로 관리하기 쉽게 되어 있음

### 3.3.1 AWS LAM이란?

AWS IAM : Identity and Access Management(ID와 접속 관리)의 약어로 AWS의 인증 기능
- AWS 계정 : 계약을 관리하는 계정
- IAM : 각 서비스에 대한 접속을 관리하는 기능
- IAM 사용자 : 사람에 대해 부여하는 IAM

### 3.3.2 IAM 그룹과 IAM 정책
- IAM 사용자, IAM 역할 두 가지 모두에 필요한 최소한의 기능을 부여하고, 필요한 사람에게만 전달하여 운영하는 것이 기본
- 사용자는 IAM 그룹으로 그룹화 가능 : 그룹화를 통해 같은 권한을 부여하고 싶은 사용자를 일괄로 관리할 수 있음
- IAM 정책 : 실행자가 어떤 서비스에 접속할 수 있는지 정해진 규칙을 설정하는 기능 
-> 실행자가 무엇을 할 수 있는지 개별로 설정 X, 정책을 적용하는 형태로 설정
=> 권한 설정을 변경하고 싶을 때도 정책만 변경하면 OK
=> 정책은 실행자 한 명에 대해 여러 설정을 할 수 있고, 정책 한 개를 여러 사용자나 역할에 설정 가능

### 3.3.3 IAM 정책 설정하기

- IAM 정책은 '무엇에 대해 어떤 조작을 허가할지 말지' 설정
- 자격 기반 정책 : 실행자가 '어떤 일을 할 수 있는가'의 형태로 설정 가능
- 리소스 기반 정책 : 조작 대상에 대해 '무엇을 허가할 것인가'의 형태로 설정 가능
- 기본적으로는 미리 준비되어 있는 AWS 관리 정책 사용을 추천

## 3.4 Amazon CloudWatch : Amazon EC2의 리소스 상태
- Amazon CloudWatch : 서버의 모니터링을 도와주는 서비스

### 3.4.1 Amazon CloudWatch란?
- Amazon CloudWatch : 각 AWS 서비스의 리소스 모니터링과 관리를 담당하는 서비스
- AWS의 각 서비스에서 지표, 로그 등을 수집, 기록
- 수집한 로그가 임계 값을 넘으면 특정 동작이 일어나도록 설정 가능 -> 감시 상황에 대처하는 관리 가능

### 3.4.2 사용 가능한 조작과 Amazon CloudWatch Logs
- Amazon CloudWatch로 CPU 사용률, 볼륨의 읽기 쓰기 횟수나 바이트 수, 네트워크 송수신 패킷 수 등 감시 가능
- Amazon CloudWatch Logs : 각종 로그 기록 가능
- 범용적인 로그
- AWS CloudTrail : 감사 서비스 활성화 -> 누가 어떤 리소스에 접근했는지도 기록으로 남길 수 있음

## 3.5 AWS Billing and Cost Management : AWS 비용 관리
- 비용 관리 도와주는 서비스

### 3.5.1 AWS Billing and Cost Management란?
- AWS Billing and Cost Management : AWS 요금을 관리해 주슨 서비스
- 요금 납부, 사용료 모니터링, 비용/사용 현황 보고 등 사용 가능

#### <기능>
- AWS Cost Explorer를 사용해 비용 확인 가능
- AWS Budgets는 비용이 특정 임계 값을 넘었을 때 알림을 발송할 수 있는 구조로 되어 있음
- 비용과 사용 현황 보고서는 비용과 사용 현황에 대한 자세한 데이터가 1일 1회 CSV 형식으로 Amazon S3의 S3 버킷에 저장됨

## 3.6 리전과 가용 영역 : 세계 각국에 존재하는 데이터 센서
- 리전 : 간단하게 말해서 데이터 센터
- AWS는 세계 각국에 대해 데이터 센터 존재

### 3.6.1 리전과 가용 영역
- AWS는 전 세계 25 지역에 서버와 데이터 센터를 가지고 있음
- 이러한 지리적 분류가 리전
- 사용자가 서비스를 사용할 때 지역을 지정함
- 각 리전에는 여러 가용 영역이 각각 물리적으로 독립된 설비로 설치되어 있음
=> 데이터 센터의 설비가 여러 장소에 분산되어 있음!
- 가용 영역은 각각 클라우드의 독립된 파티션, 병용함으로써 서비스의 중단 방지
- 여러 가용 영역(AZ)에 의한 구성은 이중화임

### 3.6.2 리전과 서비스
- 리전에 따라 제공되는 서비스와 제공되지 않는 서비스가 있기 때문에 '서비스 제공의 모체'이기도 함
- 제공하지 않는 서비스만 다른 리전을 선택해서 사용
- 또한 다른 지역 리전이 저렴하게 서비스를 제공하면 다른 지역 리전을 사용하기도 함
- 어떤 리전을 선택해도 콘솔의 대시보드에서 관리하기 때문에 한국어 조작 가능
