### 1과목 소프트웨어 설계
2. UML 모델 관계
1. 연관(Association) : 두 사물의 관계를 나타내는데, 연결과 상호작용까지만 있으면 해당
2. 의존(Dependeny) : 한 사물(클래스 또는 객체)의 명세가 변경되면 다른 사물에 영향을 주는 관계
3. 실체화(Realization) : 인터페이스를 구현하는 클래스 간의 관계
4. 일반화(Generalization)

13. GoF 디자인 패턴 (= 생구행)
- 생성 패턴 : Abstract Factory, Builder, Factory Method, Prototype, Singleton (= 추빌팩프싱)
- 구조 패턴 : Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy (= 어브컴데퍼플프)
- 행위 패턴 : 위에 해당 안 하면 싹 다 행위 패턴

- Strategy : 행위 패턴, 클라이언트에 영향 받지 않는 독립적 알고리즘 선택 패턴
- Prototype : 생성 패턴, 원본 객체 복제

15. 럼바우 객체 지향 분석 기법(=객/동/기)
- 객체 모델링 = 객체 다이어그램 <= 정보 모델링, 시스템에서 요구
- 동적 모델링 = 상태 다이어그램 <= 제어, 흐름, 동작
- 기능 모델링 = 자료 흐름도(DFD)

18. UI
- CLI(Commeand Line Interface) : 텍스트 형태로 이뤄진 인터페이스
- GUI(Graphical User Interface) : 마우스로 선택해 작업을 하는 그래픽 환경의 인터페이스
- NUI(Natural User Interface) : 사용자의 말이나 행동으로 기기를 조작하는 인터페이스
- VUI(Voice User Interface) : 사람의 음성으로 기기를 조작하는 인터페이스
- OUI(Organic User Interface) : 모든 사물과 사용자 간의 상호작용을 위한 인터페이스

20. 소프트웨어 아키텍처
- 파이프 필터 아키텍처 : 데이터 통로인 파이프를 토앻 컴포넌트인 필터 간의 데이터를 전송하는 구조, 단방향/양방향 모두 구현 가능, 필터 간 이동시 오버헤드 발생

### 2과목 소프트웨어 개발

25. 테스트 드라이버
테스트 드라이버(Test Driver)
- 시험 대상 모듈을 호출하는 간이 소프트웨어
- 필요데 따라 매개변수를 전달하고, 모듈을 수행한 후 결과를 보여줄 수 있음
- 상향식 테스트에서 사용
테스트 스텁(Test Stub)
- 제어 모듈이 호출하는 타 모듈의 기능 간단 수행 도구
- 하향식 테스트에서 사용

27. 스택
- Overflow : 스택 공간이 가득 찼을 때, 하나의 데이터를 더 넣으려고 하는 경우, 스택 오버플로우 발생
- Underflow : 스택 공간에 데이터가 없을 때, 스택에서 데이터를 꺼내려고 하는 경우, 언더플로우 가능

28. 소프트웨어 개발 활동
- 결함(Fault) : 오류 및 작동 실패의 원인으로서, 개발자의 설계와 다르게 동작 or 제작 의도와 다른 결과가 발생하는 것
- 실수(Mistake) : 사람이 저지른 잘못된 판단이나 결심을 가리킴

36. 소프트웨어 품질 목표
- 이식성(Protability) : 다양한 하드웨어 환경에서도 운용 가능하도록 쉽게 수정될 수 있는 능력 (쉽게 이식 가능!)
- 효율성(Efficiency) : 최소의 작업으로 요구되는 기능을 수행하는 정도
- 사용 용이성(Usebility) : 소프트웨어를 쉽게 사용할 수 있는 정도
- 정확성(Correctness) : 사용자의 요구사항을 충족시키는 정도
- 신뢰성, 무결성, 유지보수 용이성, 검사 용이성, 상호 운용성, 유연성, 재사용성

37. 검색 시간 복잡도
최악의 경우
- 이진 탐색 트리 : O(n)
- AVL 트리 : O(log n)
- 2-3 트리 : O(log 3n)
- 레드-블랙 트리 : O(log n)

39. 테스트 수행 도구
- 자료 흐름도, 기능 테스트, 입력 도멩니 분석, 랜덤 테스트
- 스터브, 드라이버 => 통합 테스트 시에 사용
- 스터브(Stub) : 하향식 테스트에 사용되는 테스트용 임시 모듈
- 드라이브(Drive) : 상향식 테스트에 사용되는 테스트 가동기

40. 저작권 관리 구성 요소 중 패키저(Packeager)의 역할
- 패키저 : 콘텐츠를 메타 데이터와 함께 배포 가능한 단위로 묶는 기능
디지털 저작권 관리(DRM) 구성 요소
- 콘텐츠 제공자 : 콘텐츠 제공 저작권자
- 콘텐츠 분배자 : 암호화된 콘텐츠 제공
- 패키저 : 콘텐츠를 메타 데이터와 함께 배포 가능한 단위로 묶는 기능
- DRM 컨트롤러 : 배포된 콘텐츠의 이용 권한 통제
- 클리어링 하우스 : 소비자와 유통업자 사이에 발생하는 거래에 대해 디지털 저작권 라이선싱을 중개하고 라이선스 발급을 수행하는 장소

### 3과목 데이터베이스 구축

41. 데이터베이스의 무결성 규정(Integrity Rule)
- 개체 무결성 : 모든 테이블이 기본키로 선택된 컬럼을 가져야 함
- 참조 무결성 : 참조 관계의 두 테이블 데이터가 항상 일관된 값을 갖도록 유지하는 것
- 도메인 무결성 : 테이블에 존재하는 필드의 무결성 보장을 위한 것
- 무결성 규칙 : DB에서 무결성 규칙은 데이터 무결성을 지키기 위한 모든 제약사항을 의미

42. 뷰
- 뷰(View) : 하나 이상의 기본 테이블로부터 유도되어 만들어지는 가상 테이블
- 튜플 : 관계 데이터 구조 테이블에서 행
- 카디널리티 : 튜플의 갯수
- 트랜잭션 : 하나의 논리적 기능을 수행하기 위한 작업의 단위 or 한꺼번에 모두 수행되어야 할 일련의 연산들

49. 관계형 데이터베이스 - key
- 기본키 : 후보키 중에서 선정된 main key, 특정 튜플을 유일하게 구별할 수 있는 속성 / 중복 X / NULL 값 X
- 슈퍼키 : 유일성 만족 속성 or 속성들의 집합
- 후보키 : 유일성, 최소성 만족 속성 or 속성들의 집합
- 대체키 : 기본키로 선택되지 못한 후보키
- 외래키 : 다른 릴레이션의 기본키를 참조하는 속성 or 속성들의 집합

51. 로킹
로킹(병행 제어 기법 중 하나)
- 직렬화 기법
- 로킹 단위 : 한꺼번에 로킹할 수 있는 객체의 크기
- 로킹 단위가 큼 => 로크의 수가 적어짐 => 병행성 수준 낮아짐, 병행 제어 기법 간단해짐
- 로킹 단위 작음 => 로크의 수 많아짐 => 데이터 베이스 공유 증가, 로킹 오버헤드 증가

53. 이상 현상(Anomaly)
- 데이터 정규화가 되지 않은 테이블에서 연산을 수행할 시 데이터에 생기는 논리적 오류
- 삽입 이상 : 자료 삽입 시 아직 정해지지 않은 부분에 대한 NULL값 등을 삽입해야 함
- 갱신 이상 : 데이터 수정 시 중복된 다른쪽 데이터가 수정되지 않아 생긴 모순된 데이터
- 삭제 이상 : 한 정보를 삭제했을 때 의도하지 않게 해당 행의 다른 데이터까지 삭제되는 현상

54. DDL, DML, DCL
1) DDL(definition)
- CREATE, ALTER, DROP
2) DML
- SELECT, INSERT, DELETE, UPDATE
3. DCL(control)
- COMMIT, ROLLBACK, GRANT, REVOKE

55. 정규화
- 논리적 설계 단계에서 수행하는 작업
- 데이터 구조의 안정성 최대화
- 중복을 배제하여 삽입, 삭제, 갱신 이상의 발생 방지
- 데이터 삽입 시 릴레이션을 재구성할 필요성을 줄임

56. 동시성 제어를 위한 직렬화 기법
- 로킹 기법 : 같은 자원으 액세스하는 다중 트랜잭션 환경에서 DB의 일관성과 무결성을 유지하기 위해 트랜잭셕의 순차적 진행을 보장하는 직렬화 기법
- 타임스테프 기법 : 트랜잭션과 트랜잭션이 읽거나 갱신한 데이터에 대해 트랜잭션이 실행을 시작하기 전 타임스탬프를 부여하여 부여된 시간에 따라 트랜잭션 작업을 수행하여 트랜잭션 간의 처리 순서를 미리 정하는 기법

### 4과목 프로그래밍 언어 활용

64. C언어
- strcat() : 문자열을 이어 붙여주는 기능
- strcat(str, p2) : str과, p2를 붙여 str에 저장하겠다

66. C언어
- r1 = b <= 4 || c ==2;
=> r1은 뒤 조건 중 하나 이상 만족하면 1 아니면 0
- r2 = (a> 0) && (b < 5) 
=> r2는 뒤 조건 둘 다 만족하면 1 아니면 0
- r3 = !c; (c ==2, 숫자 2는 0 이외의 모든 수라서 참 !을 붙여서 거짓)

71. 포인터
- &n : 변수 n의 주소값
- *pt : 포인터 pt가 가리키고 있는 주소에 저장된 값
- *&pt : *(포인터 pt의 주소값) = 포인터 pt의 주소가 가리키고 있는 주소에 저장된 값 = 변수 n의 주소

74. 프로세스
- 디스패치(Dispatch) : 준비 -> 실행
- 할당 시간 초과(Time Run Out) : 실행 -> 준비
- 대기(Block) : 실행 -> 대기
- 깨움(Wake Up) : 대기 -> 준비

- PCB : 운영체제가 그 프로세스를 관리할 때 필요한 모든 정보를 유지하는 자료구조 테이블
- 문맥 교환 : CPU가 현재 실행하고 있는 프로세스의 상태를 PCB에 저장하고 다음 프로세스의 PCB로부터 문맥을 복원하는 작업
- 스레드 : 프로세스 실행 단위

78. 페이지 교체 알고리즘
- OPT - Optimal : 앞으로 가장 오랫동안 사용되지 않을 페이지 교체
- FIFO - Frist-In-Frist-Out : 선입선출
- LRU - Least Recently Used : 가장 오랫동안 사용되지 않은 페이지 교체
- LFU - Least Frequently Used : 참조 횟수가 가장 적은 페이지 교체
- MFU - Most Frequently Used : 참조 횟수가 가장 많은 페이지 교체
- NUR - Not Used Recently : 최근에 사용하지 않은 페이지 교체

### 5과목 정보시스템 구축 관리

81. 침입 탐지 시스템(IDS : Intrusion Detection System)
- 이상 탐지 : Behavior, Statistical Detection으로 불리며, 평균적 시스템의 상태 기준으로 비정상적인 행위나 자원의 사용이 감지되면 이것을 알려줌
- 오용 탐지 : Signature Base나 Knowledge Base로 불리며 미리 입력해 놓은 공격 패턴이 감지되면 이를 알려줌

82. 접근 제어
- 강제 접근 통제(Mandatory Access Control) : 주체와 객체의 등급을 비교하여 접근 권한 부여
- 임의 접근 통제(Discretionary Access Control) : 접근하는 사용자의 신원에 따라 접근 권한 부여
- 사용자 계정 컨트롤(User Access Control) : 프로그램에서 관리자 수준의 권한이 필요한 작업을 수행할 때 사용자에게 알려져 제어할 수 있도록 돕는 기능
- 자료별 접근 통제(Data-Label Access Control > Label-Based Access Control) : 개별 행, 열에 대해 쓰기 권한, 읽기 권한을 가졌는지 명확하게 결정하는 제어 방식

87. VLAN, STP, ARP
VLAN(Virtual Local Area Network)
- 물리적 배치와 상관없이 논리적으로 LAN 구성
- 브로드캐스트 도메인을 구분할 수 있게 해 주는 기술로 접속된 장비들의 성능 향상 및 보안성 증대 효과
STP(Spanning Tree Protocal)
- 2개 이상의 스위치가 여러 경로로 연결될 때, 무한 루프 현상을 막기 위해 우선 순위에 따라 1개 경로로만 통신하도록 하는 프로토콜
APP(Address Resolution Protocol)
- 네트워크 상에서 IP 주소를 물리적 네트워크 주소로 대응시키기 위해 사용되는 프로토콜

89. 암호화 알고리즘
- 대칭키 암호화 - 블록 암호화 방식 : DES, SEED, AES, ARIA
- 개인키 암호화 - 스트링 암호화 방식 : LFSR, RC4
- 공개키 암호화(비대칭 암호) : RSA

90. Software Definde Storage
- 스토리지에 가상화를 적용
- 소프트웨어로 전체 스토리지 자원을 관리하여 하나의 저장장처럼 사용할 수 있도록 하는 기법

91. Cocomo 모델
SW 비용 추정 모형
1) Cocomo 모델 : LOC(Line of Code) 기반 비용 선정 방식
- Embeded : 초대형 규모 시스템 소프트웨어 대상
- Organic : 기관 내부의 중소 규모 sw 대상
- Semi-Detached : Embeded와 Organic 중간 
2) Putnam 모델 : Rayleigh-Norden 곡선의 노력 분포도를 이용한 비용 산정 방식
- 기능 점수 모델 : 기능 점수를 산출하여 비용 산정

96. MQTT(Message Queuing Telemetry Transport) 프로토콜
- IBM 개발
- 발행/구독 프로토콜
- TCP/IP를 통해 실행되어 기본 네트워크 연결 제공

- MLFQ : 짧은 작업이나 입출력 위주의 프로세스에 우선순의를 부여하는 선점형 스케줄링 기법
- Zigbee : 홈 네트워크 및 무선 센서망에서 사용되는 기술로, 버튼 하나의 동작으로 집안 어느 곳에서나 전등 제어 및 홈 보안 시스템을 제어 관리하는 가정 자동화를 목표로 출발함

98, Hash, Encryption
- Hash : 단방향, 복호화 불가능
- Encryption : 양방향, 역으로 복호화 가능
