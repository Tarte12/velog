# 1. 네트워크 계층의 역할

## 1.1 네트워크 간의 연결 구조
- **네트워크 계층**: 서로 다른 네트워크에 있는 목적지로 데이터를 전송하기 위해 필요
- 데이터 링크 계층으로는 **같은 네트워크 내에서만** 데이터 전송 가능
- **네트워크 계층 역할 => 다른 네트워크 간의 통신을 가능하게 하는 것**
- **라우터**(router): 네트워크 계층을 통해 다른 네트워크로 데이터를 전송하기 위한 네트워크 장비
	- 데이터와 목적지가 정해지면 **해당 목적지까지 어떤 경로로 가는 것이 좋은지** 알려주는 기능을 함
    - 데이터를 보내려는 상대가 어디있는지 모르면 목적지까지의 경로 알려주지 못함
- **IP 주소**: 네트워크를 식별할 수 있는 주소
	- **어떤 네트워크의 어떤 컴퓨터인지** 구분할 수 있게 해 주는 주소
    - IP 주소가 있으면 다른 네트워크에 있는 목적지 저장 가능
- **라우팅**(routing): 목적지 IP 주소까지 **어떤 경로**로 데이터를 보낼지 결정하는 것
	- 라우팅은 라우터라는 장비가 필요
    - 라우터 테이블(routing table): 라우터에서 경로 정보를 등록하고 관리할 때 필요
    
## 1.2 IP(Internet Protocol)

# 2. IP 주소의 구조
## 2.1 IP 주소 = 주소
- **IP 주소**: 데이터를 다른 네트워크의 목적지로 보낼 때 필요
	- **인터넷 서비스 제공자**(ISP)에게 IP 주소를 받을 수 있음
    - IP 버전: **IPv4**, **IPv6**
    - IPv4가 32비트로 되어 있어 IP 주소를 약 43억 개 만들 수 있었는데, 인터넷이 보급되면서 이게 부족해져서 IPv6 주소(128 비트)가 등장하게 됨
- **공인 IP 주소**:
	- 인터넷 서비스 제공자(ISP)가 제공
    - IPv4는 주소의 수가 고갈 중 -> 인터넷에 직접 연결되는 컴퓨터나 라우터에 공인 IP 주소 할당
- **사설 IP 주소**
	- 회사나 가정의 랜에 있는 컴퓨터에는 사설 IP 주소 할당
    - 랜 안에 있는 컴퓨터에는 랜의 네트워크 관리자가 자유롭게 사설 IP 주소를 할당하거나 라우터의 DHCP 기능을 사용하여 주소 자동 할당
    - DHCP: Dynamic Host Configuration Protocol
    	- IP 주소를 자동으로 할당하는 프로토콜
- 공인 IP 주소, 사설 IP 주소는 모두 2진수의 32비트를 동일하게 사용
- MAC 주소 => 48비트, 16진수
- IP 주소 => 32비트, 10진수
- 옥텟(octet): 8비트

- IP주소 = 네트워크 ID + 호스트 ID
	- 네트워크 ID: 어떤 네트워크인지
    - 호스트 ID: 해당 네트워크의 어느 컴퓨터인지
    
# 3. IP 주소의 클래스 구조
## 3.1 IP 주소 클래스

- IPv4의 IP 주소는 32비트 
	- 비트로 구분하지만
    - 네트워크 ID를 크게 만들거나, 호스트 ID를 작게 만들어 네트워크 크기 조정 가능
    - 네트워크 크기 => **클래스**로 구분
    
 [일반 네트워크] A ~ C 클래스
 - A 클래스: 대규모 네트워크 주소
 	- 8비트 네트워크 ID, 24비트 호스트 ID
 - B 클래스: 중형 네트워크 주소
 	- 16비트 네트워크 ID, 16비트 호스트 ID
 - C 클래스: 소규모 네트워크 주소
 	- 24비트 네트워크 ID, 8비트 호스트 ID
    
 - D 클래스: 멀티캐스트 주소
 - E 클래스: 연구 및 특수 용도 주소

# 4. 네트워크 주소와 브로드캐스트 주소의 구조
## 4.1 네트워크 주소와 브로드캐스트 주소

IP 주소에 네트워크 주소와 브로드캐스트 주소가 있음

- 네트워크 주소: 전체 네트워크에서 **작은 네트워크**를 식별하는 데에 사용
	- 호스트 ID가 10진수로 0 => 그 네트워크 전체를 대표하는 주소가 됨
    - 전체 네트워크의 대표 주소가 되는 것
- 브로드캐스트 주소: 네트워크에 있는 컴퓨터나 장비 모두에게 **한 번에 데이터를 전송**하는 데 사용되는 전용 IP 주소

# 5. 서브넷의 구조
## 5.1 서브넷

- 서브넷팅(subneting): 네트워크를 분할하는 것
	- 대규모의 네트워크를 작은 네트워크로 분할하여 브로드캐스트로 전송되는 패킷의 범위를 좁힐 수 있음
    - 이럴 경우 더 많은 네트워크를 만들 수 있어 IP 주소를 더 효과적으로 활용 가능
- 서브넷(subnet): 분할된 네트워크

서브넷팅으로 작은 네트워크로 분할할 경우,
-> 네트워크 ID + 호스트 ID => 네트워크 ID + 서브넷 ID + 호스트 ID 구성으로 나눠짐
	- 원래 호스트 ID로 사용되던 비트를 서브넷 ID로 바꾸는 것
    - 호스트 ID에서 비트를 빌려 서브넷으로 만들 수 있음
    
## 5.2 서브넷 마스크
- 서브넷 마스크: **네트워크 ID**와 **호스트 ID**를 식별하기 위한 값
	- IP 주소를 서브넷팅했을 때 어디까지가 네트워크 ID고 호스트 ID인지 판단하기 어려울 때 서브넷 마스크 값을 사용
- 프리픽스 표기법: 서브넷 마스크를 **슬래시**(/비트 수)로 나타낸 것
	- ex) 255.255.255.0 => /24
    
# 6. 라우터의 구조
## 6.1 라우터란

- 라우터(router)
	- 서로 다른 네트워크와 통신하려면 라우터 필요
    - 네트워크를 분리할 수 있음
    - 스위치만 있는 네트워크는 모든 컴퓨터와 스위치가 동일한 네트워크에 속하게 됨(허브도 마찬가지)
    - 근데 라우터가 있으면 이 네트워크를 분할할 수 있음
- 기본 게이트웨이(default gateway)
	- 네트워크 출입구 설정
    - 컴퓨터 1이 다른 네트워크에 데이터를 전송할 때 라우터의 IP 주소를 설정해야 함
- 라우팅 테이블
	- 수동으로 등록: 소규모 네트워크에 적합
    - 자동으로 등록: 대규모 네트워크에 적합
- 라우팅 프로토콜: 라우터 간에 라우팅 정보를 교환하기 위한 프로토콜
	- 라우팅 프로토콜을 설정하여 라우터 간에 경로 정보를 서로 교환하고 그것을 라우팅 테이블에 등록
    - RIP, OSPF, BGP 등이 있음
