> ** B tree 개념& 특징
B tree 데이터 삽입 방식 **

### 이진 탐색 트리(BST)
- 모든 노드의 왼쪽 서브 트리는 해당 노드의 값보다 작은 값들만 가지고, 모든 노드의 오른쪽 서브 트리는 해당 노드의 값보다 큰 값들만 가진다
- 자녀 노드는 최대 두 개까지
- IF 만약 자녀 노드의 개수를 늘리고 싶다면?

### B Tree
- 자녀 노드의 최대 개수를 늘리기 위해 -> 부모 노드에 Key를 하나 이상 저장
- 부모 노드의 Key들을 오름차순으로 정렬
- 정렬된 순서에 따라 자녀 노드들의 Key값의 범위가 결정됨

=> 이런 방식을 사용하면 자녀 노드의 최대 개수를 입맛에 맞게 결정해서 쓸 수 있음
** B tree는 BST를 일반화한 tree **

- 최대 몇 개의 자녀 노드를 가질 것인지가 B tree를 사용할 때 중요한 파라미터!

### 파라미터
- M : 각 노드의 최대 자녀 노드 수
=> 최대 M개의 자녀를 가질 수 있는 B tree를 M차 B tree라 부른다
- M-1 : 각 노드의 최대 key 수
- ⌈M/2⌉ : 각 노드의 최소 자녀 노드 수  
(root node, leaf node 제외)
- ⌈M/2⌉-1 : 각 노드의 최소 key 수 
(root node 제외)

- internal 노드의 key 수가 x개라면, 자녀 노드의 수는 언제나 x+1개
- 노드가 최소 하나의 key는 가지기 때문에 => 몇 차 B tree인지와 상관없이 internal 노드는 최소 두 개의 자녀는 가짐
- M이 정해지면 root 노드를 제외하고 internal 노드는 최소 ⌈M/2⌉개의 자녀 노드를 가질 수 있게 됨

### B tree 데이터 삽입
- 데이터의 추가는 항상 leaf 노드에 한다
- 노드가 넘치면 가운데(median) key를 기준으로, 좌우 key들은 분할하고 가운데 key는 승진
- 모든 leaf 노드들은 같은 레벨에 있다
=> balanced tree : 항상 일정한 성능을 낼 수 있음
=> 검색 avg/worst case : O(logN)

> ** B tree 데이터 삭제 방식 **

### B tree 데이터 삭제
- 삭제도 항상 leaf 노드에서 발생!
- 삭제 후 최소 key 수보다 적어졌다면 재조정 필요
1. key 수가 여유 있는 형제의 지원을 받음
2. 1번이 불가능하면 부모의 지원을 받고 형제와 합침
3. 2번 후에 부모에 문제가 있다면 거기서 다시 재조정 필요

### 삭제 후 최소 키보다 적다면

1. key 수가 여유 있는 형제의 지원을 받음
1.1 동생(왼쪽 형제)이 여유가 있으면
-> 동생의 가장 큰 key를 부모 노드의 나와 동생 사이에 둔다
-> 원래 그 자리에 있던 key는 나의 왼쪽에 둔다
1.2 그게 아니라 형(오른쪽 형제)이 여유 있으면
-> 형의 가장 작은 key를 부모 노드의 나와 형 사이에 둔다
-> 원래 그 자리에 있던 key는 나의 가장 오른쪽에 둔다

2. 형제의 지원이 불가능하면 부모의 지원을 받고 형제와 합친다
2.1 동생이 있으면 동생과 나 사이의 key를 부모로부터 받는다
-> 그 key와 나의 key를 차례대로 동생에게 합친다
-> 나의 노드 삭제
2.2 동생이 없으면 형과 나 사이의 key를 부모로부터 받는다
-> 그 key와 형의 key를 차례대로 나에게 합친다
-> 형의 노드 삭제

3. 부모가 지원한 후 부모에게 문제가 있다면 상황에 맞게 대응
3.1 부모가 root 노드가 아니라면
-> 그 위치에서부터 다시 1번부터 재조정을 시작
3.2 부모가 root 노드고 비어있다면
-> 부모 노드 삭제
-> 직전에 합쳐진 노드가 root 노드가 됨

### internal 노드 데이터 삭제
- leaf 노드에서 삭제하고 필요하면 재조정
- internal 노드에 있는 데이터를 삭제하려면, leaf 노드에 있는 데이터와 위치를 바꾸고 삭제
=> 그렇다면 leaf 노드에 있는 데이터 중 어떤 데이터와 위치를 바꿀 것인가?
=> 삭제할 데이터의 선임자나 후임자와 위치를 바꿔 준다
- 선임자(predecessor) : 나보다 작은 데이터들 중 가장 큰 데이터
- 후임자(successor) : 나보다 큰 데이터들 중에서 가장 작은 데이터

### B tree 데이터 삭제 정리
- 삭제는 항상 leaf 노드에서 발생
- internal 노드의 경우 선임자와 위치 바꾼 후 삭제
- 삭제 후 최소 key 수보다 적어졌다면 재조정
- 형제 지원 -> 부모 지원 받고 형제 합침 -> 부모 도움 후 부모도 문제 시 재차 조정
