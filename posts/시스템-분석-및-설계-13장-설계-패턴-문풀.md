13.1 다음 중 설계 패턴을 적용하는 장점으로 거리가 먼 것을 3개 선택하라
1) 객체 사이의 관계 파악을 돕는다
2) 메소드 내부 알고리즘 설계를 돕는다
3) 수정이 용이한 설계를 가능하게 한다
4) 사용자의 요구 파악을 용이하게 한다
5) 도메인 객체 파악을 돕는다
6) 적절한 객체를 발견하도록 돕는다

(2) 설계 패턴은 객체 간의 구조나 상호작용을 정의, 세부적인 알고리즘 설계와 관련 X
(4) 설계 패턴은 구현 단계의 문제를 해결하기 위한 것이며, 요구 분석 단계와 관련 적음
(5) 설계 패턴은 도메인 객체를 파악하기보단 객체 간의 상호작용 및 관계 설계에 초점

13.2 다음은 GoF의 4개 설계 패턴이다. 각 문제에 대한 설계 패턴을 4개 중 골라라.
설계 패턴
1) Singleton
2) Adaptor
3) Template Method
4) Observer
문제
1) 생성자 메서드를 private로 선언, 객체 생성을 책임지는 메서드를 가짐 -> Singleton
2) 포장 클래스라고 부름 -> Adaptor
3) GoF의 패턴 분류에서 '생성' 패턴에 속함 -> Singleton
4) publisher-subscriber 패턴이라고 부름 -> Observer
5) 공통 알고리즘에 대한 제어와 관리 용이 -> Template Method
6) 객체 사이의 1:N 의존 관계 정의 -> Observer
7) 기존 인터페이스 구현, 대체 인터페이스 참조하는 클래스 생성 -> Adaptor
8) GoF에 의한 패턴에서 '구조' 패턴에 속함 -> Adaptor
9) 알고리즘에 대한 기본 구조가 유사할 때 사용 -> Template Method
10) 자바 GUI 컴포넌트들의 이벤트 처리에 적용 -> Observer
11) 관찰 대상인 Subject 인터페이스 정의 -> Observer
12) 클라이언트 코드를 최소한으로 수정하기 위해 이용 -> Adaptor
13) 컴퓨터 자원을 소비하는 객체 생성에 이용 가능 -> Singleton
14) 프레임워크 개발에 유용하게 이용 가능 -> Template Method
15) 특정 객체의 상태 변화를 다른 객체들에게 자동으로 통지 -> Observer
16) 기존 클래스를 외부 클래스로 대치하는 것이 필요할 때 이용 -> Adaptor
17) 특정 메서드의 약간의 단계에 대한 추상 연상 정의 -> Template Method

13.4 다음 문제에 대하여 괄호에 적절한 용어를 적어라
- 도메인 객체 모델로부터 분석 객체 생산을 돕기 위해 구문 분석 방법과 (1)을 적용할 수 있으며,
- 분석 객체 모델로부터 품질 좋은 설계 객체 모델 생산을 돕기 위해 낮은 결합도와 높은 응집도 외에도 CRC 카드와 (2)을 적용할 수 있음

객체 식별 / 설계 패턴

13.5 다음 각 문제의 괄호를 채워라
- Singleton 패턴은 단일 객체 생성을 위해 생성자 메서드를 (1)로 선언 -> 외부에서 객체 생성을 못하게 하고, 내부 메서드 접근만을 통해 객체 생성이 가능하도록 함
- 또한 단일 객체에 대한 용이한 접근을 위해 내부 메서드를 (2)로 선언

private / public

- Adaptor 패턴은 기존 클래스를 외부 대체 클래스로 대치하기 위해 Adaptor 클래스를 생성하는 것이 필요
- Adaptor 클래스는 기존 클래스에 대한 인터페이스를 (3)하고 대체 인터페이스를 (4)하는 것이 필요

사용 / 의존, 참조

- Template Method 패턴은 공통 알고리즘에 대한 기본 구조가 유사할 때 사용
- 공통 알고리즘의 기본 구조에 해당하는 템플릿 메소드는 서브 클래스에서 변경할 수 없도록 (5)로 선언하고,
- 템플릿 메소드의 약간의 단계들은 (6) 메소드로 정의하여 서브 클래스에서 다시 구현하도록 강요

final / 추상

- Observer 패턴은 특정 객체의 상태 변화를 등록된 다른 객체들에게 통지할 필요가 있을 때 사용
- 이때 관찰 대상이 되는 특정 객체를 위해 (7)이라 하고,
- 통지되는 다른 객체들을 (8)이라 한다
- 자바 라이브러리는 Observer 패턴을 지원하기 위해 관찰 대상이 되는 특정 객체를 위해 (9) 클래스를 제공하며, 
- 통지되는 다른 객체들을 위해 (10) 인터페이스를 제공

Subject / Observer / Observable / Observer
