# 04-1 ALU와 제어 장치
> CPU의 구서 요소 중 ALU와 제어 장치를 알아보기
> ALU와 제어 장치가 어떤 정보를 내보내고 받아들이는지를 중심으로 두 장치의 역할 학습

**CPU** : 저장된 명령어를 읽고, 해석하고, 실행하는 장치
**<내부>**
- ALU : 계산 담당
- 제어 장치 : 명령어를 읽고 해석하는 장치
- 레지스터 : CPU 내에 있는 작은 임시 저장 장치
## ALU
![](https://velog.velcdn.com/images/emprimula/post/ce6553c6-4efb-42bf-8250-fba87fe069ee/image.png)

**ALU** : 계산을 수행하는 장치
- 레지스터에서 저장된 피연산자를 받아들임
- 제어 장치에서 수행할 연산을 알려주는 제어 신호 받아들임
- 피연산자와 제어 신호를 통해 다양한 연산 수행
- 연산을 위해 여러 회로들이 존재하며, **가산기, 보수기, 시프터, 오버플로우 검출기** 등이 존재

### ALU 회로
- 가산기 : 덧셈을 위한 회로
- 보수기 : 뺄셈을 위한 회로
- 시프터 : 시프트 연산을 수행하는 회로
- 오버플로우 검출기 : 오버플로우를 대비한 회로

>오버플로우가 뭐임?

### ALU가 내보내는 정보
- ALU 연산 수행 결과 : 특정 숫자, 문자, 메모리 주소 등
- 빠른 접근 속도를 위해 결과는 일시적으로 레지스터에 저장
- **플래그** : ALU가 연산 결과와 함께 내보내는 추가 정보
=> CPU가 프로그램을 실행할 때 참고해야 하는 정보로 레지스터에 저장됨

### ALU가 내보내는 대표적인 플래그
- 부호 플래그 : 연산 결과의 부호가 음수인지
- 제로 플래그 : 연산 결과가 0인지
- 캐리 플래그 : 연산 결과에서 올림수나 빌림수가 발생했는지
- 오버플로우 플래그 : 오버플로우(연산 결과가 저장할 레지스터 공간보다 큰 상황)가 발생했는지
- 인터럽트 플래그 : CPU가 인터럽트가 가능한지
- 슈퍼바이커 플래그 : 현재 프로그램이 커널 모드(1)인지, 사용자 모드(0)인지

## 제어 장치
![](https://velog.velcdn.com/images/emprimula/post/06ea3e83-daed-4444-8f4e-23efbb18f1a7/image.png)

**제어 장치** : 제어 신호를 내보내고 명령어를 해석하는 부품
- 컴퓨터 부품들을 관리하고 작동시킬 때 사용되는 전기 신호인 제어 신호를 내보냄
- 제어 장치는 CPU 구성 요소 중 가장 정교하게 설계된 부품이라 할 수 있으며, 제조사마다 제어 장치 설계에 차이 존재

### 제어 장치가 받아들이는 정보

**1. 클럭 신호를 받아들임**
- 클럭(Clock) : 컴퓨터의 시간 단위로 부품들은 클럭 주기에 맞춰 명령어, 연산 등이 처리됨
**2. 해석해야 할 명령어를 받아들임**
- 명령어 레지스터로부터 명령어를 받아들이고 해석하여 제어 신호를 발생시킴
-
**3. 플래그 레지스터 속 플래그 값을 받아들임**
**4. 시스템 버스와 제어 버스를 통해 제어 신호를 받아들임**

### 제어 장치가 내보내는 정보

**1. CPU 외부에 전달하는 제어 신호**
- 제어 버스로 제어 신호를 내보냄
- 메모리에 전달하는 제어 신호와 입출력 장치에 전달하는 제어신호 등이 존재

**2. CPU 내부에 전달하는 제어 신호 **
- ALU에 전달하는 제어 신호, 레지스터에 전달하는 제어 신호가 있음

-> 각 제어 신호들은 부품들의 역할에 맞는 역할을 수행하는 명령을 담고 있음

# 04-2 레지스터
> 레지스터의 종류와 역할
> 각 레지스터를 통해 명령어가 처리되는 과정

- 레지스터: 프로그램 속 명령어, 데이터를 실행 전후로 저장하는 장치

## 반드시 알아야 할 레지스터

**1. 프로그램 카운터(Program Counter, PC)
- 명령어가 저장된 주소를 저장
- 명령어 포인터(Instruction Pointer, IP)라고도 불림

**2. 명령어 레지스터(Instruction Register, IR)
- 명령어를 저장
- 프로그램 카운터에 지정된 위치의 명령어를 저장하는 레지스터
- 제어 장치는 명령어 레지스터 속 명령어를 읽고 해석해어 제어 신호를 발생시킴

**3. 메모리 주소 레지스터(Memory Address Register, MAR)
- 메모리의 주소를 저장하는 레지스터
- 주소값이 주소 버스를 통해 CPU를 오갈 때 메모리 주소 레지스터를 거침

**4. 메모리 버퍼 레지스터(Memory Buffer Register)
- 메모리와 주고받을 데이터와 명령어를 저장하는 레지스터
- 메모리 데이터 레지스터(Memory Data Register, MDR)이라고도 불림

**5. 범용 레지스터(General Purpose Register)
- 일반적으로 자유롭게 사용할 수 있는 레지스터
- 여러 값(데이터, 주소 등)을 모두 저장할 수 있음
- 일반적으로 CPU 내에는 여러 개의 범용 레지스터 존재

**6. 플래그 레지스터(Flag Register)
- 연산 결과나 CPU 상태의 부가적 정보를 저장하는 레지스터

**레지스터 동작 원리**
![](https://velog.velcdn.com/images/emprimula/post/b5cdbbaf-3609-4b31-a7be-2611f7f87b17/image.png)

(1) 프로그램이 메모리에 위치한 처음 주소가 프로그램 카운터에 저장
(2) 프로그램 카운터에 있는 주소를 메모리 주소 레지스터에 전달
(3) 메모리 주소 레지스터가 주소 버스를 통해, 메모리 읽기라는 제어 신호가 제어 버스를 통해, 메모리에 전달
(4) 메모리는 해당 위치에 저장된 값을(1000번지에 저장된 값)을 데이터 버스를 통해 메모리 버퍼 레지스터로 전달
(5) 프로그램 카운터는 다음 데이터가 저장된 주소로 갱신
(6) 메모리 버퍼 레지스터에 저장된 값은 명령어 레지스터로 이동
(7) 제어 장치는 명령어 레지스터에 있는 명령어를 해석하고 제어 신호 발생시킴
(8) 위의 과정을 반복하며 CPU는 프로그램에 저장된 다음 명령어들을 반복적으로 처리함

## 특정 레지스터를 이용한 주소 지정 방식(1) : 스택 주소 지정 방식
![](https://velog.velcdn.com/images/emprimula/post/8a4caf64-6ab2-4860-ada5-34644fdb9753/image.png)
**- 스택 주소 지정 방식: 스택과 스택 포인터를 이용한 주소 지정 방식**
** 스택 포인터(Stack Pointer): 스택 주소 지정 방식에 사용되는 레지스터로, 스택의 꼭대기를 가르킴**
- 마지막에 저장한 값의 위치를 저장하는 레지스터
- 스택의 어디까지 데이터가 채워져 있는지 나타냄
**- 스택 영역 : 메모리 내에서 스택처럼 사용하기로 정한 공간들**
- 다른 주소 공간과는 분리돼 스택처럼 사용하는 영역

> 스택 주소 지정 방식의 장점, 다른 주소 공간과 분리해 스택처럼 사용하는 영역을 왜 만들었는지?

## 특정 레지스터를 이용한 주소 지정 방식(2) : 변위 주소 지정 방식
![](https://velog.velcdn.com/images/emprimula/post/3acfadf0-429c-4776-817a-dc79d4a93569/image.png)
**변위 주소 지정 방식(Displacement addressing mode): 오퍼랜드의 필드값(변위)과 특정 레지스터 값을 더해 유효 주소를 얻어내는 주소 방식**
** 변위 주소 지정 방식 사용 명령어: 연산 코드 필드, 레지스터 필드, 오퍼랜드 필드**
- 연산 코드 필드: 수행할 연산 내용이 담긴 필드
- 레지스터 필드: 더할 값을 담고 있는 필드
- 오퍼랜드 필드: 주소를 담고 있는 필드

**오퍼랜드 필드 주소에 어떤 레지스터를 더하는지에 따라 다음처럼 나뉨**
- 상대 주소 지정 방식
- 베이스 레지스터 주소 지정 방식
- CPU 종류에 따라 이것 외에도 다양한 방식 존재

### (2)-1 상대 주소 지정 방식
![](https://velog.velcdn.com/images/emprimula/post/4d51f21c-bd9a-43c9-b3c6-62d14937de93/image.png)
**상대 주소 지정 방식(Relative Addressing Mode): 오퍼랜드와 프로그램 카운터 값을 더해 유효 주소 값을 얻는 방식**
- 프로그램 카운터는 읽어드릴 명령어 주소를 가짐
- 오퍼랜드 값(k라 가정)이 더해지면서 읽어들일 주소에서 k만큼 떨어진 주소의 명령어를 실행
- 분기하여서 특정 주소의 코드를 실행할 때 사용(if문 같은 느낌)
> 왜 쓰는지 아직 이해가 잘 안 됨

### (2)-2 베이스 레지스터 주소 지정 방식
![](https://velog.velcdn.com/images/emprimula/post/72770d47-9fb8-4b4c-8309-2e6b24045e31/image.png)
** 베이스 레지스터 주소 지정 방식(Base-Register Addressing Mode): 오퍼랜드와 베이스 레지스터 값을 더해 유효 주소를 얻는 방식
- 베이스 레지스터: **기준 주소**, 오퍼랜드: **기준 주소로부터 떨어진 거리** 역할
- 베이스 레지스터 속 기준 주소로부터 오퍼랜드 값만큼 떨어진 거리의 주소 값을 유효 주소로 선택하는 방식

> 그러니까 기존 주소에 특정 오퍼랜드 값을 더해서 읽을 주소를 찾는 방식이 왜 필요한 건지 이해가 잘 안 됨 (걍 읽어들일 주소를 저장했다가 그걸 다이렉트로 읽으면 안 되는 거임?)

# 04-3 명령어 사이클과 인터럽트
> CPU가 하나의 명령어를 처리하는 흐름인 명령어 사이클
> 그 흐름을 방해하는 인터럽트

**명령어 사이클: 하나의 명령어를 처리하는 정형화된 흐름**
**인터럽트: CPU 명령어 처리 과정의 흐름을 끊는 상황**

## 명령어 사이클
**명령어 사이클(Instruction Cycle): 프로그램 속 명령어들이 실행되는 주기**
- 프로그램 속 명령어들은 명령어 사이클이 반복되며 실행됨
- 프로그램의 명령어들은 일반적으로 인출과 실행 사이클이 반복되며 실행됨
- 간접 사이클이 추가되는 경우 존재

**인출 사이클(Fetch Cycle): 메모리에 있는 명령어를 CPU로 가져오는 단계**
- 위 레지스터 동작 원리의 (1)~(6) 단계

**실행 사이클(Excution Cycle): CPU로 가져온 명령어를 실행하는 단계
- 제어 장치가 명령어의 레지스터 값을 해석하고 제어 신호를 발생시킴

**간접 사이클(Instruction Cycle): 명령어를 실행하기 위해 메모리 접근을 한번 더 하는 과정
- 간접 주소 지정 방식의 경우 유효 주소의 주소에 접근하기 위해 메모리 접근이 한번 더 필요함
> 이 설명 부가적으로 찾아봐야 할 듯

## 인터럽트
**인터럽트(Interrupt): CPU의 작업을 방해하는 신호**
- CPU가 처리할 다른 작업이 생길 때 발생
- 우선순위 존재
- 동기 인터럽트와 비동기 인터럽트 존재

**동기 인터럽트(Synchronous Interrupts): CPU에 의해 발생하는 인터럽트**
- CPU가 명령어를 수행하면서 예상치 못한 상황이 생겼을 때 발생
- 예외(Exception)이라고도 불림

**비동기 인터럽트(Asynchronous Interrupt): 입출력장치에서 발생하는 인터럽트**
- 키보드, 마우스 등의 입력이나 프린터의 작업 완료 등으로 발생
- 입출력 작업 발생 시 나타남
- 일반적인 인터럽트, 하드웨어 인터럽트라고도 불림
- 인터럽트 발생으로 입출력 작업 결과를 확인하여 CPU의 생산 효율을 높임

**하드웨어 인터럽트 처리 순서**
(1) 입출력장치는 CPU에 인터럽트 요청 신호를 보냄
(2) CPU는 실행 사이클 종료 후 명령어를 인출하기 전 인터럽트 여부 확인
(3) CPU는 인터럽트 요청이 존재할 시, 인터럽트 플래그 상태를 통해 인터럽트를 수용할 수 있는지 체크
(4) 인터럽트 수용이 가능하다면 CPU는 지금까지 작업 내용을 백업
(5) CPU는 인터럽트 벡터를 참조해 인터럽트 서비스 루틴 실행
(6) 인터럽트 서비스 루틴 종료 후, (4)에서 백업한 작업을 복구해 다시 실행

**용어**
**- 인터럽트 요청 신호**: 입출력장치에서 CPU에 인터럽트를 요청하는 신호
**- 인터럽트 플래그(Interrupt flag)**: 하드웨어 인터럽트를 수용할지 여부 결정 플래그
-  CPU가 인터럽트 요청을 받아들이려면 인터럽트 플래그가 활성화되어 있어야 함
- CPU가 중요 작업을 처리 중이거나 방해 신호를 받지 않을 땐 0으로 설정, 이땐 인터럽트 요청을 무시함
- 정전이나 하드웨어 고장으로 발생하는 인터럽트는 플래그가 0이더라도 CPU가 요청 무시 불가능
- 플래그가 인터럽트 요청을 막을 수 있는 인터럽트인지 여부에 따라 막을 수 있는 인터럽트(maskable interrupt)와 막을 수 없는 인터럽트(non maskable interrupt)로 나뉨

**-인터럽트 서비스 루틴(Interrupt Service Routine, ISR)**: 인터럽트를 처리하는 프로그램
- 인터럽트 발생 시 해당 인터럽트를 어떻게 처리하고 작동할지에 대한 정보를 가짐
- 인터럽트 핸들러(Interrupt Handler)라고도 불림

**-인터럽트 벡터(Interrupt vector)**: 인터럽트 서비스 루틴을 식별하는 정보
- 수많은 인터럽트 서비스 루틴을 구분하는 정보
- CPU는 인터럽트 벡터를 통해 인터럽트 서비스 루틴의 시작 주소를 알 수 있음
- CPU는 하드웨어 인터럽트 요청을 보낸 대상으로부터 인터럽트 벡터를 데이터 버스를 통해 전달받음

**인터럽트 백업 과정**
- 인터럽트가 발생하면 실행 중이던 작업 내용은 스택에 백업
-> 프로그램 카운터 등 프로그램 재실행에 필요한 모든 정보를 저장
-> 인터럽트 서비스 루틴이 끝나면 스택 영역으로 돌아와 작업 재개

## 예외의 종류
- 동기 인터럽트의 종류?

**폴트(fault)**: 예외 처리 후, 에외가 발생한 명령어부터 다시 실행하는 예외
**트랩(trap)**: 예외 처리 후, 예외 발생 다음 명령어부터 실행하는 예외
- 주로 디버깅할 때 사용
- 특정 코드가 실행되는 순간을 출력(디버깅) 후 다시 재개할 때 다음 코드부터 실행하면 됨
**중단(abort)**: CPU가 실행 중인 프로그램을 강제로 중단시켜야 하는 심각한 오류를 발견했을 때 발생하는 예외
**소프트웨어 인터럽트(sofrware interrupt)**: 시스템 호출이 발생했을 때 나타나는 예외
