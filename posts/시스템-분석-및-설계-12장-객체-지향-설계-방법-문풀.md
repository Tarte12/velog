12.1 계층 구조에서 경계 클래스와 도메인 클래스 중간에 위치하는 제어 클래스의 역할에 대한 설명으로 거리가 먼 것을 3개 선택하라
1) 경계 클래스가 도메인 클래스에게 메시지를 직접 요청하도록 한다
2) 경계 클래스와 도메인 클래스는 자신의 역할에만 집중하도록 돕는다
3) 경계 클래스와 도메인 클래스 사이의 결합도를 증가시킨다
4) 시스템 외부 환경과 시스템 내부 사이의 연결을 최소화한다
5) 비즈니스 로직 및 데이터 관리에 대한 책임을 갖는다

(1) 제어 클래스 : 경계 클래스와 도메인 클래스 사이의 중재 역할
-> 직접 요청하면 제어 클래스의 존재 이유가 없어짐
(3) 제어 클래스의 역할 : 경계 클래스와 도메인 클래스 간의 결합도를 감소 + 두 클래스가 자신의 역할에만 집중하도록 돕는 것
(5) 비즈니스 로직 및 데이터 관리 => 도메인 클래스의 역할
- 제어 클래스는 흐름/상호작용만 관장하며 비즈니스 로직에 관여 X

12.2 다음은 CRC 카드에 대한 내용, 괄호에 적절한 단어를 적어라

- 사용사례 실현과 클래스 책임 분산을 위해 효과적으로 이용될 수 있는 CRC 카드에서,
- 카드의 앞면은 해당 클래스에 대한 (1) 책임을 나열하며,
- 뒷면은 (2) 책임을 나열한다
- 이때 아는(Knowing) 책임은 채당 클래스의 (3)에 해당하며,
- 수행 책임은 클래스의 (4)에 해당한다

(1) 책임 (2) 협력자 (3) 속성(Attributes) (4) 동작(Methods)
- CRC 카드(Class, Responsibility, Collaboration) : 클래스의 책임과 협력자를 정의하기 위한 도구, 객체지향 설계에서 자주 사용

12.3 다음은 UML 3-계층 구조에서 도메인 계층에 대한 내용, 괄호에 적절한 단어를 적어라
- UML 3-계층 구조는 경계 계층, 도메인 계층, 데이터 관리 계층으로 구성
- 도메인 계층은 영속성이 있는 도메인 클래스에 해당하는 (1) 클래스와,
- 사용사례 수행을 위해 전체적인 흐름을 관장하는 (2) 클래스를 포함
- 도메인 계층은 (3) 계층이라고도 부름

(1) 엔터티 클래스: 도메인 계층에서 영속적 데이터 관리 담당
(2) 제어 클래스 : 사용사례 흐름 관장
(3) 비즈니스 로직(or 어플리케이션 계층) : 시스템의 핵심 로직 구현

12.4 다음은 양질의 객체 지향 설계를 위한 결합도와 응집도에 대한 내용, 괄호에 적절한 단어를 적어라
- 품질 좋은 객체지향 설계를 위해 상호작용 결합도는 (1)하고,
- 클래스 응집도는 (2)하는 게 필요
- 여기에서 상호작용 결합도는 클래스 사이의 (3) 관계 또는 (4) 관계에 의한 결합 정도를 의미,
- 클래스 응집도는 단일 클래스와 클래스에 포함된 (5)과 (6)이 얼마나 밀접하게 관련되는지 의미

최소화 / 최대화 / 연관 / 의존 / 속성 / 연산(Methods)
- 결합도 : 클래스 간 의존성 정도, 낮을수록 유연성이 높아짐
- 응집도 : 클래스 내부 구성 요소(속성과 연산)의 관련성을 의미, 높을수록 단일 책임 원칙에 부합

12.6 3-계층 클래스 구조화를 위해 이용되는 UML 다이어그램과 기능 모델링을 위해 이용되는 UML 다이어그램을 적어라

- 3-계층 구조화를 위한 UML 다이어그램 : 클래스 다이어그램
- 기능 모델링을 위한 UML 다이어그림 : 활동 다이어그램

12.7.2 UML 3-계층 구조에서 데이터 접근 클래스는 데이터 관리 계층, UI 클래스는 경계 계층이라 부른다 -> 엔터티 클래스와 제어 클래스는 무슨 계층이라고 부르는가?
- 도메인 계층
12.7.3 데이터 접근 계층이 없다면 발생하는 문제점에 대하여 설명하라, 당신의 설명에 '2-계층', '응집도', '책임' 단어를 포함하라
- 데이터 접근 계층이 없으면 2-계층 구조가 형성되어 UI 계층과 비즈니스 로직 계층이 직접적으로 데이터에 접근하게 됨
- 이로 인해 응집도 낮아짐
- 데이터 접근과 관련된 책임이 분산
- 유지보수와 확장성이 저하됨

12.8 다음은 객체지향 설계 활동에서 생성되는 모델들과 이용되는 다이어그램에 대한 내용, 괄호에 적절한 단어를 적어라
- 설계 활동에는 시스템 아키텍처 모델, 설계 객체 모델, 사용사례 실현 모델을 생성
- 시스템 아키텍처 모델을 생성하기 위해 (1), 패키지, (2) 다이어그램을 이용하며,
- 설계 객체 모델을 생성하기 위해 (3) 다이어그램을 이용
- 사용사례 실현 모델을 생성하기 위해 (4) 다이어그램을 이용

컴포넌트 / 배치 / 클래스 / 시퀀스
- 시스템 아키텍처 모델 : 컴포넌드 다이어그램, 배치 다이어그램
- 설계 객체 모델 : 클래스 다이어그램
- 사용사례 실현 모델 : 시퀀스 다이어그램
