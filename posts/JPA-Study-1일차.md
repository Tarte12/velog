# 1장 JPA 소개
## 서두
 - ORM(Object Reational Mapping) : 객체와 관계형 데이터베이스 간의 차이를 중간에서 해결해 주는 프레임 워크
 - JPA : 자바 진영의 ORM 표준
 - CRUD SQL 작성 필요 X
 - 데이터 저장 계층에 작성해야 할 코드의 간소화
 - SQL이 아닌 객체 중심 개발 
 - 생산성과 유지보수가 좋아짐
 - 텍스트 작성 편리해짐
 
##  1.1 SQL을 직접 다룰 때 발생하는 문제점
###  문제점
 - 진정한 의미의 계층 분할이 어려움 : DAO(데이터 접근 객체)를 열어서 직접 SQL을 확인해야 하는데, 이것은 매우 SQL에 의존적임
 - 엔티티를 신뢰할 수 없음 : SQL에 모든 것을 의존하기 때문에
 - SQL의 의존적 개발을 피할 수 없음
###  JPA
 - JPA 제공 API 사용 : 개발자가 직접 SQL 작성 X -> 알아서 JPA가 적절한 SQL을 생성함
##  패러다임의 불일치 : 객체와 관계형 데이터베이스 간의 패러다임 차이
### 상속
- 객체 : 상속 기능 O
- 테이블 : 상속 기능 X
- 슈퍼타입 서브타입 관계를 사용하면 유사하게 설계하는 척은 가능
- 코드를 완성하려면 상속 기능이 없으므로 객체에 맞춰서 다 SQL을 따로 작성해야 함
- 이 과정이 매우 비효율적
- JPA는 자바 컬렉션에서 객체를 정의하듯 JPA에게 객체를 저장하면 상속 문제 해결
