10.1 소프트웨어 설계 대상이 아닌 것은?
1) 컴포턴트(= 모듈 설계)
2) 데이터
3) 프로젝트 범위
4) 소프트웨어 구조

(3) 프로젝트 범위 : 소프트웨어 설계 대상은 주로 시스템 구성요소와 이들 사이의 관계, 데이터, 컴포넌트, 인터페이스를 포함 / 프로젝트 범위는 요구사항 정의 단계에서 다룸

10.2 모듈 설계에서 취해야 할 주요 작업 내용은?
1) 소프트웨어 시스템 개념애 대한 정의와 실현 가능성 확인
2) 시스템 개발 계획 및 요구기능의 정의
3) 프로그램의 제어구조, 자료구조, 인터페이스 및 알고리즘 구성
4) 각 프로그램에 대한 코딩 및 부분 테스트

(3) 모듈 설계는 소프트웨어의 세부적인 제어구조, 자료구조, 인터페이스 정의, 알고리즘 설계에 중점

10.3 다음 중 소프트웨어 아키텍처를 표현하기 위해 사용되는 표기법으로 가장 거리가 먼 것은?
1) 클래스 다이어그램
2) 흐름도
3) 개체관계도
4) 구조도

(2) 흐름도는 프로그램의 논리적 흐름을 표현하지만, 소프트웨어 아키텍처를 표현할 때 적합하지 않음
- 아키텍처 표현 : 클래스 다이어그램, 객체 관계도, 구조도 사용

10.4 소프트웨어 설계에서 사용되는 대표적인 3가지 추상화 기법으로 가장 거리가 먼 것은?
1) 제어 추상화
2) 기능 추상화
3) 정보은닉 추상화
4) 자료 추상화

(1) 제어 추상화
- 소프트웨어 설계의 추상화 기법 : 기능 추상화, 정보 은닉 추상화, 자료 추상화

10.5 다음 중 추상화 설계에 대한 내용으로 가장 거리가 먼 것은?
1) 상세한 것을 배제, 주요 문제에만 집중하는 설계 방법
2) 일련의 절차들을 결합하여 의미 있는 이름 부여
3) C언어에서 구조체 개념은 절차 추상화의 보기일 수 있음
4) 자바의 클래스 개념은 데이터 추상화의 보기일 수 있음

(3) C언어의 구조체 : 데이터 추상화의 예시

10.6 아키텍처(구조) 설계에 대한 설명 중 가장 거리가 먼 것은?
1) 모듈 설계와 비교하여 상위수준에서의 설계를 의미
2) 소프트웨어 아키텍처와 시스템 아키텍처 설계로 분류 가능
3) 모듈에 대한 알고리즘을 정의
4) 시스템이나 소프트웨어의 구성 요소들 사이의 관계 정의

(3) 아키텍처 설계는 시스템의 상위 수준 설계, 모듈 간의 관계와 시스템 구조 정의
- 모듈 내부 알고리즘 설계 : 세부적인 모듈 설계의 영역

10.7 다음 중 설계에 대한 설명으로 거리가 먼 것을 3개 선택
1) 요구 만족을 위한 기술 솔루션에 중점
2) 구현 플랫폼에 독립적인 논리적 모델 생성
3) 비기능 요구를 반영하는 데에 중점
4) 문제 도메인에 대한 이해에 중점
5) 검증을 위해 사용자 포함
6) 소프트웨 요구 명세서(SRS) 이용

(4), (5), (6)
- 설계는 기술 솔루션 구현과 논리적 모델 생성에 초점
- 문제 도메인에 대한 이해, 사용자의 참여 -> 요구 분석 및 명세 단계에서 중점

10.8 시스템의 논리적 모델과 물리적 모델의 차이를 설명하라. 설명에 '플랫폼', '분석', '설계'를 포함하라

(1) 논리적 모델
- 설계 초기에 작성되는 플랫폼 독립적 모델
- 시스템의 기능적 관점을 중점적으로 분석
- 분석 단계에서 주로 생성

(2) 물리적 모델
- 설계 후반에 작성되는 플랫폼 종속적 모델
- 시스템이 실제 환경에서 구현되고 배포되는 방식 정의
- 설계 단계에서 주로 작성
- 하드웨어 및 소프트웨어 구성 요소와 이들의 배치 정보를 포함함

10.9 다음 분석과 설계에 대한 내용 중 거리가 먼 것을 3개 선택
1) 분석은 검증을 위해 사용자를 포함시킴
2) 분석에서 생성되는 모델을 논리적 모델이라 부름
3) 설계는 사용자의 기능 요구 파악에 중점을 둠
4) 설계는 구현될 플랫폼을 고려하여 작성
5) 설계 모델은 문제 도메인에 대한 비즈니스 프로세스 표현
6) 분석은 논리적 모델을 물리적 모델로 변형하는 활동

(1), (3), (5)
- 분석 단계에서 검증 포함 X
- 설계는 기능 요구 X 시스템 구현에 중점
- 비즈니스 프로세스 -> 분석 단계에서 다룸
