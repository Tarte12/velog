1.2.2 연관관계
객체 : 참조를 사용해 다른 객체와 연관관계를 가짐 -> 참조에 접근해서 연관된 객체 조회
테이블 : 외래키를 사용해 다른 테이블과 연관관계를 가짐 -> 조인을 사용하여 연관된 테이블 조회
1.2.3 객체 그래프 탐색
-  SQL을 직접 다루면 처음 실행하는 SQL에 따라 객체 그래프를 어디까지 탐색할 수 있는지 정해짐
-> 비즈니스 로직에 따라 사용하는 객체 그래프가 다른데 언제 끊어질지 모를 객체 그래프를 함부로 탐색할 수 없기 때문에 객체 지향 개발자에겐 너무 큰 제약임
-JPA를 사용하면 객체 그래프 마음껏 탐색 가능
1.2.5 정리 : JPA가 패러다임의 불일치 문제를 해결해 주고 정교한 객체 모델링을 유지하게 도와줌

1.3 JPA는 무엇인가?
JPA : 자바 진영의 ORM 기술 표준으로 애플리케이션과 JDBC 사이에서 동작
ORM : 객체와 관계형 데이터베이스를 매핑
ORM 프레임워크 : 객체와 테이블을 매핑해서 패러다임의 불일치 문제를 개발자 대신 해결
-> 내가 ORM 프레임워크에 대충 저장하면 얘가 알아서 SQL문 생성해서 처리해 주는 느낌??
장점
- 개발자 대신 SQL 생성
- 다양한 패러다임 불일치 문제 해결
- 정교한 객체 모델링 가능

1.3.1 JPA 소개
JPA는 쉽게 말해서 인터페이스를 모아 놓은 개념 -> 따라서 JPS를 구현한 ORM 프레임워크를 선택해야 JPA를 사용할 수 있음
1.3.2 왜 JPA를 사용해야 하는가?
- 생산성 : 노가다를 얘가 해 줌
- 유지보수
- 패러다임 불일치 해결
- 성능
- 데이터 접근 추상화와 벤더 독립성
- 표준 : 표준을 사용하면 다른 구현 기술로 변경하기 쉬움

마이바티스와의 차이 : 결국 개발자가 SQL을 직접 작성해야 하므로 SQL에 의존하는 개발을 피할 수 없는데 반해 JPA를 사용하면 ORM 프레임워크가 대신 관련 처리를 해 주므로 SQL 의존 개발을 벗어날 수 있음
