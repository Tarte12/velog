> 컴퓨터가 데이터를 읽어들이고 이를 이해하고 표현하는 방식에 대해

# 02-1 0과 1로 숫자를 표현하는 방법
## 정보 단위
### 비트(bit) : 컴퓨터가 이해하는 가장 작은 정보 단위로 0과 1을 나타냄
- 이후의 정보들은 여러 비트의 조합으로 나타내게 됨
- 1비트는 0과 1, 두 가지 정보를 표현할 수 있음
- n비트는 2^n개의 정보를 표현할 수 있음

### 바이트(byte) : 1byte = 8bit
- 2^8(256) 정보량 표현 가능
- 킬로바이트(kB, Kilobyte) : 1kB = 1000byte
- 메가바이트(MB, Megabyte) : 1MB = 1000kB
- 기가바이트(GB, Gigabyte) : 1GB = 1000MB
- 테라바이트(TB, Terabyte) : 1TB = 1000GB

### 워드(word) : CPU가 한번에 처리할 수 있는 데이터 처리
- 워드의 크기는 CPU의 종류마다 다름 -> 보통 현대 컴퓨터는 32bit or 64bit 처리
- 하프 워드(half word) : 워드의 절반 크기
- 폴 워드(full word) : 워드의 전체 크기
- 더블 워드(double word) : 워드의 2배 크기
- 보통 CPU 제조사 인텔 사의 32bit 워드의 CPU는 x86, 64bit의 워드는  x64로 불림



## 이진법

### 십진법(decimal) : 일상적으로 우리가 사용하는 수 체계로 0~9의 10개 숫자로 모든 수 표현
- 십진수 : 십진법으로 표현한 수
### 이진법(binary) : 수학에서 0과 1만으로 모든 숫자를 표현
- 이진수 : 이진법으로 표현한 수를 지칭

**이진수의 사용법**
- 컴퓨터는 0과 1만 알기 때문에, 데이터를 이진수로 처리
- 이진수는 해당 자리수가 1을 넘어가면 자리 올림
> - 0 -> 0
>- 1 -> 1
>- 2 -> 10
>- 3 -> 11
>- 4 -> 100
- 십진수와 이진수는 구분이 어렵기 때문에 표기법을 다르게 함
> 수학적 표기 : 1000
> 컴퓨터 표기 : 0b1000

### 이진수의 음수 표현
- 마이너스 부호를 사용하지 않고 0과 1로 음수를 표현해야 함

- 보통 2의 보수(two's complement)를 구해 이 값을 음수로 간주
- 어떤 이진수의 2의 보수는 **모든 0과 1을 뒤집고, 거기에 1을 더한 값**으로 구할 수 있음
- 실제로 2의 보수가 음수인지 확인하기 위해서는 2의 보수를 두 번 구하면 됨

- 단순하게 0과 1을 뒤집는 1의 보수도 사용될 수 있지만 한계가 명확

- 음수를 나타내기 위해 2의 보수를 처리한 이진수가 일반 이진수의 값이 같을 때 문제 생길 수 있음 
- 1011(2)의 음수는 2의 보수로 0101(2)로 표현되는데, 십진수 5의 이진수도 0101(2)로 표현된다면 어떻게 구분할 것인가?
**=> 플래그! 통해 해결**
- 플래그(flag) : 어떤 수가 양수인지 음수인지 구분하는 부가 정보

- but 2의 보수도 한계 존재
1. 0을 음수로 표현할 때 문제 발생
2. 2^n을 음수로 표현할 때 문제 발생

**이진법 특징**
- 장점 : 이진법으로 숫자를 표현하면 컴퓨터가 이해하는 숫자 정보를 직접적으로 표현 가능
- 단점 : 0과 1로 모든 숫자를 표현하기 때문에 길이가 과해짐

## 십육진법 : 수가 15를 넘어가는 시점에서 자리 올림을 하는 숫자 표현 방식
- 십진수 10, 11, 12, 13, 14, 15 => A, B, C, D, E, F로 표기
- 하드웨어 관련 개발 분야에선 십육진수를 직접 쓰는 경우 존재
- 표기법
> 수학적 표기 : F(16)
> 코드 표기 : 0XF
- 십육진법은 이진수와의 변환의 쉽고 자유로워 주로 사용

# 02-2 0과 1로 문자를 표현하는 방법
## 문자 집합과 인코딩

### 문자 집합(Character Set) : 컴퓨터가 인식하고 표현할 수 있는 문자 모음
- 컴퓨터는 문자 집합에 속한 문자만 이해할 수 있음
- 문자 집합에 속한 문자는 0과 1로 변환되어야 컴퓨터가 이해할 수 있음

### 문자 인코딩(Character Encoding) : 문자를 0과 1로 변환하는 과정
- 같은 문자 집합에 대해서도 다양한 인코딩 존재
- **코드 포인트(Code Point)** : 문자에 고유한 값을 부여해서 인코딩함

### 문자 디코딩(Character  decoding) : 0과 1로 이뤄진 문자 코드를 사람이 이해할 수 있는 문자로 변환하는 과정
- 인코딩의 반대 과정

## 아스키 코드

### 아스키(ASCII)
- 초창기 문자 집합
- 영어 알파벳, 아라비아 숫자, 일부 특수 문자
- 7비트로 표현 -> 2^7 : 128 문자 표현
- 문자 표현 7비트 외에 오류 검출에 사용되는 패리티 비트(parity bit)가 1비트 사용됨

### 아스키 코드(ASCII Code) : 각 아스키 문자에 대응되는 고유한 수

### 특징
- 장점 : 아스키 코드는 매우 간단하게 인코딩됨
- 단점 : 127가지의 문자 외에 다른 문자 표현 불가능

### 확장 아스키(Extended ASCII) : 아스키 코드에 1비트를 추가해 더 다양한 문자가 표현 가능한 인코딩 방식
- 하지만 문자 표현 가능 수는 256개로 여전히 적음

## EUC-KR

### 한글 인코딩 방식 : 완성형, 조합형
- 완성형 인코딩 방식(한글 완성형 코딩) : 초성, 중성, 종성이 조합된 완성 글자 자체에 고유한 코드 부여
- 조합형 인코딩 방식(한글 조합형 코딩) : 초성, 중성, 종성 각각을 위한 비트열을 할당해 그것들의 조합으로 완성 글자를 표현

### EUC-KR : 완성형 인코딩 방식으로 인코딩 크기는 2바이트

### CP949 : 마이크로소프트에서 개발한 인코딩 방식으로 ECU-KR 확장 버전

## 유니코드와 UTF-8

### 유니코드(Unicode) : 대부분 나라의 문자, 특수문자, 화살표, 이모티콘 등을 코드로 표현할 수 있는 표준 문자 집합
- 현대 문자를 표현할 때 가장 많이 사용되는 표준 문자 집합
- 문자 인코딩에서 매우 중요한 역할
- 유니코드 부여값 앞에 U+라는 문자가 붙기도 하는데, 십육진수로 유니코드가 표시됐을 때 사용하는 표기

- 유니코드는 문자마다 값이 부여되는데, 이것을 다양한 방법으로 인코딩함
- UTF-8, UTF-16, UTF-32 등이 존재, 각 방법마다 인코딩 방식이 다름
- **UTF(Unicode Transformation Format)** : 유니코드 인코딩 방법

**UTF-8** : 유니코드를 인코딩하는 방식 중 하나
- 유니코드 문자에 부여된 값에 따라 인코딩 크기는 1byte ~ 4byte로 달라지게 됨
- 문자의 고유값이 속한 범위에 따라 인코딩 크기가 달라짐
