- 이미지 업로드처럼 엑셀 파일 업로드 기능 확장(추후 첨부파일 다운로드 기능 생각 중)

- `Notice` 도메인 중심으로 CRUD 기본 구조 구성
- 엑셀 파일 업로드 시 `NoticeExcelRow`로 변환 -> 유효성 검사 -> 엔티티 생성 -> 저장

- `BlogException` 기반으로 예외 핸들링

## ExcelRowValidator 처리 방식

| 항목    | 내용                                      |
| ----- | --------------------------------------- |
| 지금 방식 | `예외를 던지는 방식으로 유효성 검사를 수행`               |

## 유효성 검사 VS 예외 처리

> 만들다가 보니까 비슷한 느낌이 들어서 뭘 유효성 검사로 넘기고 뭘 예외 처리로 넘겨야 하는 건지 궁금해서 정리함

| 항목        | 유효성 검사 (Validation)               | 예외 처리 (Exception Handling)   |
| --------- | --------------------------------- | ---------------------------- |
| 🎯 목적     | **입력값이 올바른지 사전 검사**               | **정상 흐름 중 예기치 않은 오류 대응**     |
| 🧠 개념     | "이 값 괜찮아?"                        | "뭔가 망가졌어!"                   |
| 📍 위치     | 사용자 입력값 처리 전에                     | 예상 외 상황 발생 시                 |
| 📌 사용 시점  | 요청 들어오기 전/중                       | 런타임 중 (실행 중)                 |
| 🛠 방식     | 조건문 (`if`, `@Valid`, Validator 등) | `try-catch`, `throw new ...` |
| ⚠️ 잘못된 경우 | 사용자에게 친절히 알려줌 (400 Bad Request 등) | 시스템 에러 응답 (500, 예외 메시지)      |
| 🏗 예시     | "비밀번호는 8자 이상이여야 함"                | "DB 연결이 끊겼다", "파일이 없다"       |



# 트러블 슈팅 및 추가 수정
## stream() 예외 씹힘 문제
### 문제 상황
- 엑셀 유효성 검사를 `stream().map().collet()` 내부에서 try-catch 처리
- 예외를 던져도 Controller까지 도달하지 않고 로깅만 됨
### 분석
- Java stream 내부의 예외는 외부로 throw되어도 통상적으로 wrapping or swallowing 됨
- 특히 `.collect(Collectors.toList())`까지 마치면 더 이상 예외가 흐르지 않음
### 해결
- `for-each` 기반 loop로 로직 변경
- 각 행에 대해 개별적으로 검사하고 예외 발생 시 바로 throw

## NoticeExcelParser 삭제
- 처음엔 파싱을 `util`로 따로 빼서 해결하려고 함
- 근데 다 만들고 나니까 `NoticeExcelParser` 클래스를 사용해서 파싱하지 않고, Service 계층에서 `EasyExcel`로 직접 처리하는 구조로 만들게 돼서, 그냥 삭제하고 구조를 단순화

## 추가 수정
### 예외 메시지 구체화
- `ExcelRowValidator` 내부에서 예외 메시지 구체화
- `BlogException`에서 생성자 오버로딩으로 예외 메시지 생성자 추가한 코드 추가
### 로그 추가
- `@Slf4j`를 썼지만 로깅을 거의 안 함
- 어떤 행이 잘못됐는지, 유효성 검사가 얼마나 실패했는지 알 수 없음
- 원인 파악을 위해 로그 추가
