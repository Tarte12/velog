9장 객체 지향 분석 방법

- 구조적 : 데이터의 흐름, 프로세스, 기능
- 객체 지향 : 절차 지향 개발

소개
- 객체 중심(데이터+기능)
- 객체 사이 메시지 호출을 통한 협력(상호작용) 통해 개발
- 개념적/추상적 다이어그램 -> 실질적/구체적 다이어그램
- 분석, 설계, 구현까지 개발 전반에 걸쳐 동일한 다이어그램 이용

요구 추출(시스템 정의서)
- 첫 번째 수행 작업 : 시스템 관련 주요 특징을 최상위 수준에서 정의한 시스템 정의서(문제 정의서, 시스템 명세서) 작성
- 작성 목적
1. 모든 관계자 사이 공유
2. 위험 요소 파아고가 가능성 분석에 대한 기초 자료
3. 초기 계획 수립 기초 자료

요구 추출(도메인 객체 모델)
- 개념 모델, 도메인 모델
1. 도메인 주요 개념 객체 표현, 관계 표현
2. 솔루션 클래스(윈도우, 제어, 데이터 접근) X
3. 데이터 모델과 차이

용어 사전
- 클래스는 도메인의 주요 개념을 표현 -> 용어 사전 작성 필요
1. 도메인에서 사용되는 주요 개념과 어휘에 대한 이해
2. 개발 전반에 이용될 수 있는 공통 어휘 제공

요구 추출(상위 수준 기능 모델)
- 액터 파악하고 그들의 사용 목적 문의

사용사례 VS 사용자 이야기
사용사례
- 사용자의 전략적 비즈니스 목적을 성취하기 위해 시스템이 수행해야 하는 기능에 대한 시나리오 기술
- 주문 생성
사용자 이야기
- 사용자가 시스템에 요구하는 단순 기능 기술
- 가입, 로그온, 주문 품목 추가
- 애자일 방법에 적용

요구 분석
- 문제 도메인에 대한 깊은 이해 및 사용자 요구에 대한 명확한 정의
- 요구 추출 작업 결과물 -> 분석을 위한 기초 자료 (비즈니스 모델, 도메인 객체 모델, 상위수준 사용사례)
- 3개 모델 생성 : 기능, 정적 구조, 동적 행위

요구 분석(기능 관점)
- 시스템 성공과 실패에 지대한 영향
- 요구 추출의 사용사례를 다이어그램으로 표현 -> 더욱 상세히 분석하고 정제하여 기술
- 기능 모델 OR 사용사례 모델
1. 고객과 개발자 사이의 계약서
2. 나머지 활동에 대한 기초정보 제공
- 수행 작업
1. 사용사례 다이어그램 생성
2. 사용사례 구조화
3. 사용사례 다이어그램
4. 사용사례 상세 기술

사용사례 다이어그램 생성
- 개발 시스템이 외부 액터에게 전체적으로 무슨 서비스를 제공하는지 용이한 파악을 위해

사용사례 구조화
- 용이한 이이해와 효울적인 관리와 개발 위해 사용사례 구조화(그룹화)

사용사례 다이어그램 정제
- 용이한 이해와 사용사례 유지보수를 위해

요구 분석(정적 구조 관점)
- 도메인 객체 모델 정제하여 분석 객체 모델 생성 : 문제 도메인의 정보에 대한 더욱 깊은 이해
- 객체 모델 생성 지원을 위한 방법
1. 구문 분석 방법 : 사용사례와 같은 도메인의 문서(텍스트) 정보 활용
2. 분석 패턴 적용 방법

구문 분석 방법
1. 사용사례로부터 명사에 의한 후보 클래스 파악
2. 부적절한 클래스 제거
- 2개의 클래스가 동일 개념을 표현한다면 하나 제거
- 도메인과 무관 OR 명확하지 않은 클래스 제거
3. 클래스 사이의 관계 파악
- 동사 파악
4. 속성 파악
- 특정 명사 묘사
- 복잡한 도메인 개념이 아닌 기본 데이터 타입
5. 클래스 다이어그램 작성
- 구문 분석 방법
- 실세계 기본 지식 활용
- 유사 문제 도메인의 객체 모델(분석 패턴) 활용

분석 패턴
1. 패턴
- 공통으로 발생하는 문제에 대한 솔루션
- 유사 문제에 재사용 가능
2. 분석 패턴
- 분석에서 공통으로 발생하는 문제에 적용할 수 있는 솔루션
- 유사 문제 도메인 클래스(개념)와 클래스(개념) 사이의 관계 파악 지원
- 객체 모델 생성이나 정제 지원

요구 분석(동적 행위 관점)
- 동적 행위 관점에서 분석
- 수행 작업
1. 시스템 순서 다이어그램 생성
2. 상태기계 다이어그램 생성
