### 1과목 : 소프트웨어 설계
2. MOM(Message Oriented Middleware)
- 메시지 지향 미들웨어
- 메시지 기반 비동기형 메시지 전달 방식 미들웨어
- 온라인 업무보단 이기종 분산 데이터 시스템의 데이터 동기를 위해 많이 사용
- 즉각적 응답 X, 느려도 안정적인 응답 O

4. Use Case 구성 요소 간의 관계
- 연관(Association) : 유스케이스와 액터간의 상호작용이 있음을 표현
- 포함(Include) : 하나의 유스케이스가 다른 유스케이스의 실행을 전제로 할 때
- 확장(Extend) : 하나의 유스케이스가 다른 유스케이스의 기능을 확장할 수 있도록 하는 관계 / 확장되는 유스케이스는 추가 기능을 제공, 기본 유스케이스 없이 독립적 실행 X
- 일반화(Generalization) : 유사한 유스케이스 or 액터를 모아 추상화한 유스케이스 or 액터와 연결시켜 그룹을 만드는 것

5. 기능적 요구사항 VS 비기능적 요구사항
- 기능적 요구사항 : 시스템이 실제로 어떻게 동작하는지
- 비기능적 요구사항 : 시스템 구축에 대한 성능, 보안, 품질, 안정 등에 대한 성능, 보안, 품질, 안정성 등으로 실제 수행에 보조적인 요구사항
- ex) 차량 대여 시스템이 제공하는 모든 화면이 3초 이내에 사용자에게 보여야 한다 -> 비기능적 요구사항 (성능)

9. 다형성(Polymorphism)
- 현재 코드를 변경하지 않고 새로운 클래스 쉽게 추가 가능
- 여러 형태를 가진다는 의미, 여러 형태를 받아들일 수 있는 특징
- 오버라이딩 : 상속 관계에서 발생 / 슈퍼 클래스의 메서드를 서브 클래스에서도 동일한 메서드를 중복하여 재정의
- 오버로딩 : 한 클래스 내에서 메서드의 이름은 동일하나, 매개변수의 수나 타입을 다르게 하여 재정의

10. 인터페이스(Interface)
- 서로 다른 두 시스템이나 소프트웨어 등을 서로 이어 주는 부분 or 접속 장치 의미

12. Inheritance, Class, Encapsulation, Association
- Inheritance(상속) : 이미 정의된 상위 클래스의 모든 속상광 ㅕㄴ산을 하위 클래스가 물려받는 것
- Class(클래스) : 하나 이상의 유사한 객체들을 묶는 것
- Encapsulation(캡슐화) : 클래스 안에 관련성이 높은 속성과 연산들을 묶어서 넣는 것
- Association(연관) : 2개 이상의 사물이 서로 관련되어 있음

20. MVC(Model-View-Controller)
- 한 개의 모델에 여러 개의 뷰를 만들 수 있음
- 모델은 서브 시스템의 핵심 기능과 데이터 보관 -> MVC 패턴에서는 여러 개의 뷰를 만들 수 있음 -> 한 개의 모델에 대해 여러 개의 뷰를 필요로 하는 대화형 애플리케이션에 적합
- 전달자 역할 : Controller

### 2과목 : 소프트웨어 개발
21. 통합 테스트(Integration Test)
- 시스템을 구성하는 모듈의 인터페이스와 결합을 테스트하는 것
상향식 통합 테스트(Bottom Up Integration Test)
- 프로그램의 하위 모듈 -> 상위 모듈 방향으로 통합
- 하나의 주요 제어 모듈과 관련된 종속 모듈의 그룹인 클러스터(Cluster) 필요
하향식 통합 테스트(Test Down Integration Test)
- 상위 모듈 -> 하위 모듈 방향으로 통합
- 깊이 우선 통합법, 넓이 우선 통합법 사용
- 초기부터 사용자에게 시스템 구조 보여 줌

22. 이진 탐색
- Binary Search : low, middle, high 값을 사용
- 찾고자 하는 데이터를 중앙에 위치한 중간값과 비교
- 전제 조건 : 데이터 목록은 오름차순 정렬이 되어져 있어야 함
	1) 배열의 중간값을 찾음
    2) 중간값과 검색값 비교
    2-1) 동일하면 끝
    2-2) 중간값보다 검색값이 크다면 오른쪽 탐색
    2-3) 중간값보다 검색값이 크다면 왼쪽 탐색
    3) 위의 과정을 반복
 
23. 워크스루(Walkthrough)
- 워크스루 : 요구사항 명세서 작성자를 포함하여 사전 검토한 후, 짧은 검토 회의를 통해 결함을 발견
- 인스펙션 : 요구사항 명세서 작성자를 제외한 다른 검토 전문가들이 요구사항 명세서를 확인하며 결함 발견

25. 테스트 케이스(Test Case)
- 구현된 소프트웨어가 사용자의 요구사항을 정확하게 준수했는지 확인 위해 설계된 입력값, 실행 조건, 기대 결과 등으로 구성된 테스트 항목에 대한 명세서를 의미
- 테스트의 목표 및 테스트 방법을 결정하고 테스트 케이스 작성
- 테스트 오라클(Test Oracle) : 테스트 케이스 실행이 통과되었는지 실패하였는지 판단하기 위한 기준

29. RCS, RTS, RPC, RVS
RCS(Revision Control System)
- CVS와 다르게 소스 파일의 수정을 한 사람으로 제한
- 다수의 사용자가 동시에 파일 수정할 수 없도록 파일 잠금 방식으로 버전관리
- 다른 방향으로 진행된 개별 결과를 합치거나 or 변경 내용 추적 가능
RPC(Remote Procedure call)
- 별도의 원격 제어를 위한 코딩 없이 다른 주소 공간에서 리모트의 함수나 프로시저를 실행할 수 있게 해 주는 프로세스 간 통신
RTS(Reliable Transfer Service)
- 데이터 통신에서 신뢰성이 보장된 전송 서비스를 제공하는 프로토콜
RVS(Relative Version System)
- 파일의 상대적인 버전을 관리하는 도구
- 각 파일의 버전 차이를 저장해 파일 복원과 변경 이력 추적

31. 알고리즘
- 선형 검색 : 처음부터 끝까지 하나씩 순서대로 비교하여 원하는 값을 찾아내는 검색
- 이진 검색 : 검색을 수행하기 전에 반드시 데이터의 집합이 정렬되어 있어야 함

32. 버블 정렬
- 첫 위치부터 시작해서 오른쪽값과 비교
- ex) 9 6 7 3 5
- 96 비교 -> 69735 -> 97 비교 -> 67935 -> 93 비교 -> 67395 -> 95 비교 -> 67359 => 이게 첫 버블 정렬이 끝난 상태 PASS 1

33. IDE
- Compile : 고급 언어(사람 친화)에서 저급 언어(기계어)로 바꾸는 기능

34. Tree 순회
- 전위순회(pre order) : root -> left -> right
- 중의순회(in order) : left -> root -> right
- 휘위순회(post order) : left -> right -> root

40. 단위 테스트 도구
- CppUnit : C++ 단위 테스트 도구
- JUnit : JAVA 단위 테스트 도구

### 3과목 : 데이터베이스 구축
41. 정규화
정규화 과정(도부이결다조)
- 제1정규화 : 모든 도메인이 원자값으로만 구성
- 제2정규화 : 기본키가 아닌 속성이 기본키에 대한 완전 함수적 종속 만족 / 부분적 함수 종속 제거
- 제3정규형 : 기본키가 아닌 모든 속성이 기본키에 대해 이행적 함수 종속 관계를 만족 X 
- BCNF : 모든 결정자가 후보키인 정규형 / 종속성 보존 X
- 제4정규형 : 다치 종속 성립 -> R의 모든 속성이 A에 함수적 종속 관계를 만족
- 제5정규형 : 모든 조인 종속이 R의 후보키를 통해서만 성립

42. DB 트랜잭션 특성
- 원자성(Atomicity) : 완전하게 수행 완료되지 않으면 전혀 수행되지 않아야 함
- 일관성(Consistency) : 시스템의 고정 요소는 트랜잭션 수행 전후에 같아야 함
- 격리성(Isolation, 고립성) : 트랜잭션 실행 시 다른 트랜잭션의 간섭 받지 않아야 함
- 영속성(Durability, 지속성) : 트랜잭션의 완료 결과가 DB에 영구히 기억됨

44. SQL 구문
- 정렬 : ORDER BY
- 내림차순 : DESC
- 올림차순 : ASC

45. DB 인덱스
인덱스(Index)
- 데이터베이스 성능에 많은 영향을 주는 DBMS의 구성 요소
- 테이블과 클러스터에 연관되어 독립적인 저장 공간 보유
- 데이터베이스에 저장된 자료를 더욱 빠르게 조회하기 위해 별도로 구성한 순서 데이터
- 대부분의 데이터베이스에서 테이블을 삭제하면 인덱스도 같이 삭제
- 인덱스 생성 : CREATE
- 인덱스 삭제 : DROP

46. 저장 레코드 양식 설계
- 저장 레코드 : 물리적 데이터베이스 구조의 기본 데이터 단위
- 설계 시 고려 사항 : 데이터 타입, 데이터 값의 분포, 접근 빈도
트랜잭션 모델링 <- 개념적 설계 단계에서 하는 것
- 트랜잭션을 개념적 시스템 독립적으로 정의
- 트랜잭션의 입출력 기능, 형태만 정의
- 검색, 갱신, 혼합(검색, 갱신)

48. 데이터 사전(Data Dictionary)
- 시스템 자신이 필요로 하는 여러 가지 객체(기본 테이블, 뷰, 인덱스, 데이터베이스, 패키지, 접근 권한 등)에 관한 정보를 포함하고 있는 시스템 데이터베이스
- 시스템 카탈로그(System Catalog), 메타 데이터(Meta Data)라고도 함
- 시스템 카탈로그 자체도 시스템 테이블로 구성되어 있음 -> SQL문을 이용해 내용 검색 가능
- 사용자가 직접 갱신 불가
- SQL문으로 여러 객체에 변화를 주면 시스템이 자동 갱신

49. 데이터베이스 릴레이션
릴레이션 특징
- 튜플의 유일성 : 모든 튜플은 서로 다른값을 가짐
- 튜플의 무순서성 : 하나의 릴레이션에서 튜플의 순서 X
- 속성의 원자성 : 속성값은 원자값을 가짐
- 속성이 무순서성 : 각 속성은 릴레이션 내에서 유일한 이름을 가짐, 순서는 큰 의미 X

- Marine Navi : 소형 선박에 설치된 GPS 기반의 선박 자동 식별 장치를 기본으로 주변 선박의 이동 속도와 위치 파악
- C-V2X : 셀룰러 이동통신망을 통해 차량이 다른 차량이나 교통 인프라, 보행자, 네트워크 등과 정보를 서로 주고받는 차량 통신 기술

89. 악성 코드 유형
- Worm : 다른 컴퓨터의 취약점을 이용하여 스스로 전파 or 메일로 전파되며 스스로 증식
- Rogue Ware(가짜 백신 소프트웨어) : 사용자가 컴퓨터에 바이러스가 있다고 믿게 하여, 설치하게 만드는 형식
- Adware : 특정 소프트웨어를 실행할 때 or 자동으로 활성화되는 광고 프로그램
- Reflection Attack(반사 공격) : 송신자가 생성한 메시지를 가로챈 공격자가 그 메시지를 다시 송신자에게 재전송하여 접근 권한을 얻는 형태의 공격 방법

90. 공격 기법
- Ping of Death : 시스템 공격 기법 중 하나로 허용 범위 이상의 ICMP 패킷을 전송하여 대상 시스템의 네트워크를 마비
- Session Hijacking : 컴퓨터 시스템 정보나 서비스에 무단으로 접근하기 위해 유효한 컴퓨터 세션을 이용
- Piggyback Attack : 공격자가 다른 사용자의 연결에서 계정을 사용하지 않는 비활성 기간을 이용하여 시스템에 접근
- XSS : 웹사이트에 악성 스크립트를 주입하는 행위

95. 접근 통제 방법
- RBAC : 역할 기반 접근 통제 (권한 있는 사람만)
- DAC : 임의 접근 통제 (사용자가 그룹 신분에 따라 제한)
- MAC : 강제 접근 통제 (미리 정해진 보안 레벨과 사용자에게만)

99. IT 기술
- NFS : 네트워크 상에서 공유되는 파일 시스템
- Network Mapper : 네트워크 보안을 위한 유틸리티
- AOE Network : 어떤 프로젝트를 마치기까지 수행되는 작업의 각 단계를 그래프의 정점으로 표현하고, 작업 하나가 완료되어 다음 단계로 넘어가는 시간을 그래프의 간선으로 나타낸 방향 그래프
