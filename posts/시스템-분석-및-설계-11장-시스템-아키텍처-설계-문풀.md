11.1 시스템 아키텍처에 대한 내용. 괄호에 적절한 용어를 선택하라.
- 3-계층 클라이언트-서버 구조에서 두꺼운 클라이언트 시스템 아키텍처는 클라이언트에 (1.응용처리/2.데이터관리/3.인터페이스) 계층을 배치하고, 
- 서버에 (1.응용처리/2.데이터관리/3.인터페이스) 계층을 배치하는 구조
- 이 구조의 특징으로써 유지보수는 (1.어렵고/2.용이하고),
- 서버 부하는 (1.적고/2.많고)
- 네트워크 부하는 (1.적다/2.많다)

응용처리 / 데이터관리 / 어렵고 / 적고 / 적음

두꺼운 클라이언트 구조 
- 클라이언트에서 응용 처리 담당
- 서버는 데이터 관리만 수행
- 위 때문에 클라이언트 변경 사항이 있을 때 유지보수의 어려움
- 얇은 클라이언트 구조에 비해 네트워크 부하 적음

11.2 두꺼운 클라이언트 구조와 비교하여 얇은 클라이언트 구조에 대한 특징을 2개 선택하라.
(1) 주요 컴포넌트들이 서버에 존재
(2) 소프트웨어 유지보수가 어려움
(3) 서버의 능력은 강력해야 함
(4) 네트워크에 부하가 적음

(1), (3)

얇은 클라이언트 구조
- 클라이언트는 인터페이스만 처리
- 서버에서 주요 처리를 모두 수행
- 따라서, 서버의 능력이 강력해야 함
- 주요 컴포넌트도 서버에 존재
- 네트워크 부하가 많음
- 소프트웨어 유지보수 용이

11.3 다음 중 클라이언트-서버 아키텍처에 해당되지 않는 것은?
(1) 웹 서비스
(2) 클러스터
(3) 분산 객체
(4) 얇은 클라이언트

(2) 클러스터 : 하나의 서버가 아닌 다수의 서버가 협력하여 작업을 수행하는 구조
- 클라이언트-서버 아키텍처 범주에 속하지 않음

11.4 클라이언트-서버 구조와 비교하여 분산 객체 구조의 장점 하나를 적고, 분산 객체 구조를 지원하기 위한 다양한 분산 컴포넌트 표준 모델 중 하나만 적어라

- 유연성 :  객체 간의 통신이 네트워크를 통해 이뤄짐 -> 시스템 확장이 용이, 분산 환경에서 유연한 설계 가능
- 표준 모델 : CORBA

11.5 다음 중 시스템 아키텍처 모델링을 위한 다이어그램으로 거리가 먼 것을 2개 선택하라
(1) 사용사례
(2) 배치
(3) 컴포넌트
(4) 패키지
(5) 클래스

(2) 배치 다이어그램은 시스템의 물리적 배치를 모델링할 때 사용 -> 시스템 아키텍처 모델링을 소프트웨어 구조와 논리적 설계에 중점을 뒀다면 부적합하게 보일 수 있음
(3) 컴포넌트 다이어그램 -> 세부 구현에 초점을 맞춘 다이어그램이기 때문에 아키텍처 모델링의 상위 수준 설계와 거리가 있다고 판단하셨을 수 있음
