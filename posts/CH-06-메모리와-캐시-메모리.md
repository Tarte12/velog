# 06-1 RAM의 특징과 종류
## RAM의 특징

### RAM과 보조기억장치
**RAM: 휘발성 저장 장치**
- 휘발성 저장 장치(volatile memory): 전원을 끄면 저장된 내용이 사라지는 저장 장치
**보조기억장치(하드디스크, SSD 등): 비휘발성 저장 장치**
- 비휘발성 저장 장치(non-volatile memory): 전원이 꺼져도 저장된 내용이 유지되는 저장 장치

**CPU는 보조기억장치에 직접 접근 불가**
=> 보조기억장치에는 **보관할 대상** 저장, RAM에는 **실행할 대상** 저장

## RAM의 용량과 성능

- RAM의 용량이 작음 => 보조기억장치에 자주 접근해야 하기 때문에 프로그램 실행 시간 증가
- RAM의 용량이 큼 => 미리 많은 데이터를 RAM에 저장할 수 있기 때문에, 보조기억장치 접근 횟수가 줄어듦 
=> 많은 프로그램을 동시에 빨리 실행하는 데에 유리
- RAM 용량이 일정 수준 이상 증가한 이후에는 속도가 용량 증가폭에 비례해 증가 X

## RAM의 종류
**DRAM, SRAM, SDRAM, DDR SDRAM

### DRAM(Dynamic RAM)
- 저장된 데이터가 동적으로 변하는 RAM
- 시간이 지나면 데이터가 점차 사라짐
- 데이터 소멸을 막기 위해 일정 주기로 데이터를 다시 저장(재활성화)해야 함
- 일반적으로 사용하는 메모리
**장점**
- 소비 전력이 비교적 낮음
- 저렴함
- 집적도가 높아 대용량으로 설계하기 유리

### SRAM(Static RAM)
- 저장된 데이터가 변하지 않는 RAM
- 시간이 지나도 데이터 유지
- 캐시메모리에 주로 사용
(캐시메모리: 적은 용량이더라도 속도가 빠른 게 중요한 저장 장치)
> 캐시메모리 용도 궁금
**장점**
- DRAM보다 일반적으로 속도가 더 빠름
**단점**
- 집적도가 낮음
- 소비 전력이 큼
- 비쌈

### SDRAM(Synchronous Dynamic RAM)
- DRAM에서 발전된 형태
- 클럭 신호와 동기화됨 => 클럭에 맞춰 동작
- 클럭마다 CPU와 정보를 주고받는 DRAM
> 클럭과 동기화된 부분이 DRAM에 비교해서 어떻게 발전이 된 건지?

### DDR SDRAM(Double Data Rate SDRAM)
- 대역폭을 넓혀 속도를 빠르게 만든 SDRAM
- 대역폭(data rate): 데이터를 주고받는 길의 너비
- 한 클럭에 두 번씩 CPU와 데이터를 주고받을 수 있어 단일 SDRAM에 비해 속도가 두 배 가량 빠름
- 대역폭 크기에 따라 다른 이름으로 불리기도 함
- 대역폭 수가 늘어날수록 이전 메모리에 비해 2배 넓은 대역폭을 가짐

# 06-2 메모리의 주소 공간

**주소의 한계**
CPU는 메모리에서 실행 중인 모든 프로그램들이 메모리 어느 위치에 저장되어 있는지 알기 어려움
- 메모리에 저장된 정보는 시시각각 변하기 때문에
- 따라서, CPU가 프로그램을 이해하는 주소와 메모리 실제 주소에는 차이 존재

## 물리 주소와 논리 주소
컴퓨터에서 사용하는 주소는 물리 주소와 논리 주소 두 가지가 존재

**물리 주소(physical address)**: 정보가 실제로 저장된 하드웨어 상의 주소로 메모리가 사용함

**논리 주소(logical address)**: 실행 중인 프로그램 각각에게 부여된 주소로 CPU가 프로그램의 실행 위치를 파악할 때 사용
- CPU는 모든 프로그램의 물리 주소 이해할 필요 X -> 각 프로그램은 0번지부터 시작하는 프로그램 내의 주소 존재
- 프로그램마다 같은 논리 주소 존재 가능
![](https://velog.velcdn.com/images/emprimula/post/de21dc81-4b87-48d8-8442-7a04911369d8/image.png)

### 논리 주소와 물리 주소의 변환

**메모리 관리 장치(Memory Management Unit, MMU): 논리 주소와 물리 주소 간 변환을 해 주는 장치
- CPU와 주소 버스 사이에 위치
- CPU가 발생시킨 논리 주소와 베이스 레지스터 값을 더해 물리 주소로 변환함

**베이스 레지스터**: 프로그램의 가장 작은 물리 주소 저장
- 프로그램이 시작하는 첫 물리 주소 저장
- 프로그램 논리 주소 0번지의 물리적 위치 의미

**논리 주소**: 프로그램의 시작점으로부터 떨어진 거리를 표시

## 메모리 보호 기법

### 메모리 보호 기법
**프로그램 A를 실행할 때, CPU는 프로그램 A의 논리 주소 영역을 벗어나는 곳에 명령을 내리면 안 됨**
- 논리 주소 영역을 벗어난 곳에 명령을 실행하면 다른 프로그램의 영역을 침범해 데이터 손상 발생시킬 수 있음
- 따라서 논리 주소 범위를 벗어나는 명령어 실행을 방지하고, 실행 중인 프로그램이 다른 프로그램에 영향을 받지 않도록 보호할 방법 필요

### 한계 레지스터
- 논리 주소의 최대 크기를 저장하는 레지스터
- CPU 명령이 프로그램 주소 범위를 벗어나는 경우를 방지하는 장치
- CPU가 접근하는 논리 주소는 한계 레지스터가 저장한 값보다 크면 안 됨
- 프로그램 물리 주소 범위 : 베이스 레지스터 값 ~ (베이스 레지스터 값 + 한계 레지스터 값)

### 보호 과정
- CPU는 명령어 실행 전 항상 접근하려는 논리 주소가 한계 레지스터보다 작은지 검사
- CPU가 한계 레지스터보다 높은 논리 주소에 접근하려고 할 때, 인터럽트(트랩)을 발생시켜 프로그램 실행을 중단시킴
- 실행 중인 프로그램의 독립적 실행 공간을 형성하고, 그 범위를 넘거나 침범받지 않도록 보호

# 06-3 캐시 메모리
## 저장 장치 계층 구조
**저장 장치는 일반적으로 아래의 명제를 따름**
1. CPU와 가까울수록 저장 장치 속도는 빠름
2. 속도가 빠른 저장 장치일수록 용량이 작고 가격이 비쌈
3. 저장 장치의 장단점이 명확하기 때문에, 컴퓨터는 다양한 저장 장치를 사용

=> 저장 장치는 RAM, 보조저장장치 외에 **캐시 메모리** 사용

## 캐시 메모리

**캐시 메모리(cash memory)**
- CPU와 메모리 사이에 위치한 저장 장치로 SRAM 기반
- 레지스터보다 용량이 크고, 메모리보다 빠름
- CPU의 연산 속도와 메모리 접근 속도의 차이를 줄이려고 사용
- CPU에서 사용될 데이터를 미리 캐시 메모리로 데려와 활용
> 약간 추가 설명 찾아봐야 할 것 같음

**캐시 메모리 종류**
- CPU(코어)와 가까운 순서대로 여러 개의 캐시 메모리가 계층을 구성
- L1(level 1) 캐시: 코어와 가장 가까운 캐시 메모리
- L2(level 2) 캐시
- L3(level 3) 캐시
- 일반적으로 L1과 L2는 코어 내부에, L3은 코어 외부에 존재

|항목|비교|
|---|---|
|용량|L1<L2<L3|
|속도|L1>L2>L3|
|가격|L1>L2>L3|

**분리형 캐시(split cache)**
- 분리형 캐시: L1 캐시의 접근 속도를 조금이라도 더 빨리 하기 위해 L1 캐시를 아래처럼 분리
- L1I 캐시(Level1 Instruction): 명령어만 저장하는 캐시
- L1D 캐시(Level 1 Data): 데이터만 저장하는 캐시
![](https://velog.velcdn.com/images/emprimula/post/0bb78321-a362-4bac-af0b-f4d4557eac85/image.png)

**저장 장치 계층 구조(memory hierachy)**
- 컴퓨터가 사용하는 저장 장치들을 "CPU에서 얼마나 가까운가"를 기준으로 나타낸 것
- 여기에서 메모리는 RAM이 아닌 일반적인 저장 장치를 의미
- 상위 계층으로 갈수록 CPU와 저장 장치 사이의 거리가 가깝고, 하위 계층으로 갈수록 멀어짐
- 상위 계층과 하위 계층을 이루는 저장 장치의 특징을 이해하고 차이를 구분할 수 있어야 함
![](https://velog.velcdn.com/images/emprimula/post/3814b987-102c-4f1c-8297-e9ec81b2d8d6/image.png)

## 참조 지역성 원리
- 캐시 메모리는 CPU가 사용할 법한 대상을 예측해서 저장

**캐시 히트(cache hit)**: 자주 사용될 것으로 예측해서 캐시 메모리에 저장한 데이터가 CPU에서 사용된 경우
**캐시 미스(cache miss)**: 캐시 메모리에 저장했지만 예측이 틀려 CPU가 메모리에서 필요한 데이터를 가져오는 경우
- 캐시 미스가 자주 발생하면 CPU가 필요한 데이터를 메모리에서 가져오는 경우가 많아져 성능이 떨어짐
**캐시 적중률(cache hit ratio)**: 캐시가 히트되는 비율
- 캐시 적중률 = 캐시 히트 횟수 / (캐시 히트 횟수 + 캐시 미스 횟수)
- 일반적으로 컴퓨터의 캐시 적중률은 약 85% ~ 95% 이상
- 캐시 메모리 이점 활용을 위해 캐시 적중률 높히는 것 중요
- 캐시 메모리는 참조 지역성의 원리에 입각해 CPU가 사용할 데이터를 예측

### 참조 지역성의 원리(locality reference, principle of locality)
**CPU가 주로 메모리에 접근하는 경향을 바탕으로 만들어진 원리**
- CPU는 최근에 접근한 메모리 공간에 다시 접근하는 경향이 있음
- CPU는 접근한 메모리 공간 근처를 접근하는 경향이 있음

#### 1. 최근에 접근했던 메모리 공간에 다시 접근하는 경향
- 시간 지역성(temporal locality): 최근에 접근했던 메모리 공간에 다시 접근하는 경향
- CPU는 최근에 접근한 메모리 공간을 여러 번 참조하는 경향이 있음

#### 2. 접근한 메모리 공간 근처를 접근하는 경향
- 공간 지역성(spatial locality): 접근한 메모리 공간 근처를 접근하는 경향
- 프로그램을 실행할 때 필요한 데이터는 보통 메모리 근처에 모여있는 경향이 있음
